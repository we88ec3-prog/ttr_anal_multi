## 增量編輯規則

1. S00 每次先核對兩個儲存庫最新 `main`、本 Task 派工、T01 退回與已有已驗證知識；取得新的正式資料後，依穩定主鍵（`CLM-*`、`SRC-*`、`RR-*`、`REQ-*`、`GAP-*`、`SPEC-*`、`TEST-*`、`TaskID`、`SFD-*` 等）合併。
2. **原有 ID：就地更新官方資料欄位**；**新 ID：追加一列**；原台帳已刪除或撤銷的記錄先標記「來源已不見／需核對」，不可無條件刪列。
3. **人工欄位必須保留**。既有研究摘要、人工備註、手動待分析事項不可用新的官方欄位整張覆寫。
4. `S00_Excel_增量更新.py` 會讀取**已同步 GitHub `main` 的本機 checkout**，以 `artifact_tool` 對**現有 XLSX 檔**按 ID 進行更新，保留原 row、檔案備份、輸出 `update-history/*.json` 的欄位差異。**不會建立 Git branch、Commit、Push，也不會改 Server 或 Client。**
5. 具體的 Server 開發進度 `05_Server開發`、功能摘要、封包與欄位若缺新的機器台帳，需 S00 檢查 Server 程式碼/研究報告後審慎增量更新。**不能**因 README 描述、離線模擬或完整欄位就擅自宣稱可玩。
6. 新發現涉及「原版 Server 內部規則未知」應列為**Server 開發需求**，送 S00 合併到既有 REQ/SPEC/GAP/ADR；「Client 必需 wire／parser／UI 仍未知」則交主責 Txx 繼續分析。保留 RR ACCEPTED／T01 FULL-PASS／SPEC STABLE／Server 實作／Client 實測彼此獨立的 status。
7. 只有使用者明確要求時才變更 GitHub 正式台帳／提交，嚴守共用指令與主責限制；S00 對 Excel 增量更新本身不代表獲准寫入任何 GitHub 倉庫。

## S00／Windows 使用指令

先完成正常 checkout 的 `main` 同步：

```powershell
cd E:\Tartaros\ttr_anal_multi
git switch main
git pull --ff-only origin main

cd E:\Tartaros\ttr_server\ttr_server_roy
git switch main
git pull --ff-only origin main
```

若 `main` 本機沒有遠端最新 commit、存在合併衝突或檔案缺失，停止同步並回報。**不要 force push、不要額外建 branch。**

把 ZIP 解壓到固定工作目錄後（例如 `E:\Tartaros\Workbook\`），執行：

```powershell
python .\S00_Excel_增量更新.py `
  --workbooks 'E:\Tartaros\Workbook' `
  --analysis-dir 'E:\Tartaros\ttr_anal_multi' `
  --server-dir 'E:\Tartaros\ttr_server\ttr_server_roy' `
  --require-main
```

這只會編輯**已有**的分類 `.xlsx`，只動官方確定的欄位；`16_人工補充` 不會被覆寫。注意實際路徑按使用者本機調整。
