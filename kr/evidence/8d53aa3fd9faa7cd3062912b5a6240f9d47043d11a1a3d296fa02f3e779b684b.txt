## 一、8330E0（D 的建構；stdcall 4 參數，`ret 0x10`）（【確認】）

呼叫：`8330E0(D, A, P, G)`，呼叫點為 `82FBAA`（`82FA80` 內）。`A=&{tileW,tileH}`、`P=&{cols,rows}`、`G=G_i`（原始逐格物件）。

| D 欄位 | 內容 | 位址 |
| --- | --- | --- |
| `+0x00` | `A[0]`（磚寬，格數） | 833113 |
| `+0x04` | `A[1]`（磚高） | 833118 |
| `+0x08` | `P[0]`（每列磚數 cols） | 83311D |
| `+0x0C` | `P[1]`（磚列數 rows） | 833123 |
| `+0x10` | `(float)W / ext_x`（`W=*G[0x18]`、`ext_x=*G[0x1C]`） | 83312C..833154 |
| `+0x14` | `(float)H / ext_y` | 833136..833157 |
| `+0x18` | 磚陣列指標（見下） | 8331EC |

- `W=[G[0x18]]`、`H=[G[0x18]+4]` 為 B 內的格數維度（`G+0x18` 指向 `B+4`）；`ext_x/ext_y` 為 `G+0x1C` 所指 `B+0xC` 起的 float。因此 `D+0x10/+0x14` 與 `B+0x14/+0x18`、`C+0x14/+0x18` 是同一種縮放值（格數÷世界寬）。
- 若 `D[0x18]` 已有舊陣列，先以向量刪除釋放（833151..83317E）。
- 配置磚陣列：`rows*cols` 筆、每筆 `0x10` bytes（前綴 4 bytes 存筆數）；建構器 `689330` 只清 `[+0],[+4],[+8]`（`[+0xC]` 不清）、解構器 `837B60`（8331C3..8331D9）。
- 以 `rows × cols` 雙層迴圈（`r` 外、`c` 內）對每個磚呼叫 `837BE0`（833239..83323F）：
  - 磚記錄位址＝`D[0x18] + ((r*cols + c) << 4)`（833230..833235）。
  - 矩形 `[ebp-0x28..-0x1C] = {x0=c*tileW, y0=r*tileH, x1=x0+tileW, y1=y0+tileH}`（833209..83323C）。
- `D+0x1C/+0x20`（區域指標陣列）**不在** 8330E0 內寫入；在 `82C000..83B000` 範圍用 `mov` 掃描也沒有任何寫入 `[reg+0x1C/+0x20]`（0 筆）。→ 在已檢視的載入鏈中，區域向量保持為 `82FA80` 初始化的空值（【確認】範圍內無寫入；其他範圍【未知】）。

## 二、837BE0（單一磚的建構；`eax`＝矩形指標，stack：磚記錄、`G`；`ret 8`）（【確認】）

1. 釋放磚記錄 `[+8]` 既有位元圖並清零（837BF8..837C01）。
2. `raw = G[0x14]`（原始逐格 dword 陣列，列主序、列寬 `*G[0x18] = W`；837C08..837C14、837C4B..837C50）。
3. 呼叫 `8334A0`（矩形均勻性檢查）：
   - 均勻：`tile[4] = 該值`、`tile[0] = 1`、結束（837C2B..837C31）。
   - `8334A0`：以矩形左上第一格為基準值，逐格比較整個矩形（`cmp [..],ebx; jne → return 0`）；全相同回 1，並把基準值寫入輸出（833502..833536）。索引＝`y*W + x`。
4. 非均勻：
   - `tile[0xC] = x1-x0`（列寬/stride；837C53）。
   - 配置暫存 `(x1-x0)*(y1-y0)*4` bytes，列主序複製矩形內 dword（837C69..837CB8）。
   - `tile[4] = 格數 count`（837CD6）；`tile[8] = new + memset(0)`，大小 `ceil(count/8)` bytes（837CD9..837CF9）。
   - 逐格：若 `tmp[idx] != 0`（`cmp dword ptr [ebx+esi*4], 0; je skip`）→ 設位元：`byte[idx>>3] |= 1 << (idx & 7)`（837D08..837D2F）。
   - 釋放暫存，結束。非均勻路徑**不寫** `tile[0]`；其值保持建構器 `689330` 的 0（【確認】建構器清 `[+0]`；若同一記錄被重建，則 `tile[0]` 是否被重設為 0 未見，但 8330E0 每次先重配陣列，故為新記錄）。

## 三、與 832DA0 的完整對應（【確認】欄位；語意見下）

| 832DA0 Part B | 對應建構 |
| --- | --- |
| `G = L[0]`，`tx = cx/G[0]`、`ty = cy/G[4]` | `G`＝D；`D[0]=tileW`、`D[4]=tileH`（8330E0） |
| `tile = G[0x18] + 16*(G[8]*ty + tx)` | `D[8]=cols`；磚陣列為 `r*cols+c` 排列（8330E0） |
| `tile[0]!=0 → return tile[4]` | 均勻磚：回傳該磚的**原始 dword 值**（非布林） |
| `idx = tile[0xC]*ly + lx`、`tile[4] <= idx → 0` | `tile[0xC]=磚寬`、`tile[4]=count`（837BE0） |
| 位元圖 `tile[8]` 第 `idx` 位 | 位元＝1 ⇔ 原始 dword ≠ 0 |

結論（【確認】程式行為）：82CDF0 的回傳 1（可通行）⇔ 兩個圖層（檔案層 0、1 → `C` 槽 `+0x24`、`+0x28`）在該格的原始 dword 皆為 0。
- 「dword ≠ 0 ＝阻擋」的**遊戲語意**屬於由回傳邏輯推出的【推測】（程式只看 ≠0）。dword 的非 0 值是否區分類型（例如不同阻擋類別）：均勻磚會回傳原值、位元磚只保留 0/≠0；因此 82CDF0 只用到 0/≠0 區分。其他讀者（若有）【未知】。

層對應：`82FA80` 將 `G_i`→`D_i` 保持索引（i→i）；`82FF10` 將 `D_k`→`C` 槽 k 保持索引（k→k）。因此 **82CDF0 的 slot0／slot1＝`.bnd` 的第 0、第 1 個圖層條目**（【確認】索引對應；兩層的遊戲語意【未知】）。

## 四、磚尺寸與覆蓋（【確認】，來自 82FA80/82FD30）

- `p`＝「能整除 `W/8` 的最大 2 的冪，上限 128」；`tileW = W/p`、`cols = p`。`H` 同理。→ 磚恰好覆蓋整個網格（皆整除）。
- 例（純算術示意，非檔案數據）：`W=1024` → `W/8=128` → `p=128`、`tileW=8`。
