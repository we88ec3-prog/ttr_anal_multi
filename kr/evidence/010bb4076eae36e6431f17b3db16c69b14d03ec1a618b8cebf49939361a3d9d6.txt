## 二、82CDF0（thiscall，ecx=碰撞管理物件，eax=&(x,y)）（【確認】）

1. `ebx=[this+0x24]`；若 `ebx==0` 且 `[this+0x28]==0` -> 回傳 0（82CDFA..82CE0F）。**只有兩者皆空才提早回傳**；若僅 slot0 為空，`ebx=0` 仍會傳入 832DA0（無個別 null 檢查）。
2. 複製 (x,y) 至區域變數，呼叫 `82CE80` 夾界（不改動呼叫者的座標）。
3. `cx = trunc(x * [this+0x14])`、`cy = trunc(y * [this+0x18])`（轉換呼叫 `8FED10`；SSE2 路徑為 `cvttsd2si`＝向零截斷，非 SSE2 備援路徑未檢查）。
4. `r1 = 832DA0([this+0x28], &(cx,cy))`；`r2 = 832DA0([this+0x24], &(cx,cy))`；回傳 `((r1|r2)==0) ? 1 : 0`（82CE62..82CE69：`or; neg; sbb; lea eax,[esi+1]`）。
5. 呼叫點僅三處：`4CAC78`（4CABE0）、`545FAE`（包裝，結果轉為布林）、`546058`（迴圈中逐步加位移後重複查詢）。後兩者本次**未分析**。

### 82CE80（ecx=&(x,y)，edx=this）

- `x < 0 → 0`；`x >= [this+0xC]`（含相等）→ `[this+0xC] - 1.0f`；其餘不變。
- `y` 同理，上界為 `[this+0x10]`。
- NaN 時兩軸皆不改動（`fcompp` 無序走 jp 跳過）。
- 結果：只夾「查詢用副本」。呼叫者（4CABE0）寫入 `vtbl+0x44` 的仍是**未夾界的 cand**。（【推測】影響：超出地圖邊界的候選位置只要邊界格可通行就可能被接受；是否有其他邊界檢查本次未驗。）

## 三、碰撞管理物件的圖層表（【確認】，來自 82CD30 解構式）

`82CD30`（`this` 在 `[ebp+8]`；FAB1D0 在 `4DF00D..4DF022` 呼叫它後釋放）：

- 迴圈 32 次：對 `this+0x24 .. this+0xA0`（每槽 4 bytes，共 `0x20` 槽）內非空指標呼叫 `82CDA0`，並清為 0。
- `this+0x20`：具引用計數的控制區塊（`[+4]`、`[+8]` 以 `lock xadd` 遞減，經虛擬函式釋放）。
- `82CDA0(esi=L)`：釋放 `L+4` 指向的緩衝區並清 `L+4/L+8/L+0xC`，再釋放 `L` 本身 → **`L` 為 `{ G*, vector.begin(+4), vector.end(+8), vector.cap(+C) }`**，元素大小 8 bytes。與 832DA0 使用 `L+4/L+8` 一致。

82CDF0 只用到 slot0（`+0x24`）與 slot1（`+0x28`）。slot2..31 的使用者【未知】。

> 注意：`82CEE0`（初始化）/`82CF90`（解構）屬於 `FAB1D4` 物件，**不是** FAB1D0 的類別（4DF028..4DF034 以 82CF90 處理 FAB1D4）。其 `+0x28` 為 map 頭節點式結構，與 82CDF0 所稱的 `+0x28` 圖層指標無關，勿混用。

## 四、832DA0（stdcall 2 參數：`L`、`&(cx,cy)`；`ret 8`）（【確認】）

**Part A：區域向量迴圈（832DAA..832E18）**

- `n = (L[8]-L[4]) >> 3`；逐元素 `e = L[4] + 8*i`：`e[0]==0` 跳過；否則 `R=e[4]`。
- 條件（全部成立才查詢）：`cx > R[8]`、`cy > R[8]`、`cx < R[0xC]`、`cy < R[0x10]`（比較皆為有號；下界嚴格大於）。
- 成立時：`off=(cx-R[4], cy-R[8])`，呼叫 `837B80(edi=R+0x18, eax=&off)`，結果存 `[ebp-4]`；迴圈在 `[ebp-4]!=0` 時中止。
- 【確認】x 的下界檢查用 `R[8]`，但位移相減用 `R[4]`；兩軸下界同用 `R[8]`。此不對稱是否為原始碼筆誤或欄位語意（【未知】）。

**Part B：基礎磚格查詢（832E1A..832EB6）**

- `G=L[0]`；`tx=cx/G[0]`、`ty=cy/G[4]`（`idiv`，無除零檢查）；`lx=cx-G[0]*tx`、`ly=cy-G[4]*ty`。
- `tile = G[0x18] + 16*(G[8]*ty + tx)`（磚記錄 16 bytes；無範圍檢查）。
- `tile[0]!=0` → 回傳 `tile[4]`。
- 否則 `idx = tile[0xC]*ly + lx`；`tile[4] <= idx`（有號）→ 回傳 0；否則回傳位元圖 `tile[8]` 第 `idx` 位（byte = `tile[8] + (idx>>3)`；位元 `idx&7`）是否為 1。
- 區塊記錄（磚與 `R+0x18` 共用）：`{ uniform_flag(+0), uniform_value 或 bit_count(+4), bitmap_ptr(+8), stride(+C) }`，由 `837B80` 內容與 832E56..832EB6 一致。

**【確認·與直覺不同】** Part A 的結果 `[ebp-4]` 在 832E1A 之後**從未被讀取**；三個 `ret`（832E64、832E7F、832EB6）的 `eax` 皆來自 Part B。因此「區域向量」的查詢目前**不影響回傳值**（呼叫無寫入副作用；是否為原程式的遺漏、或在此版本被停用，【未知】）。

回傳語意：非 0＝該層該格被遮擋（由 82CDF0 取反後 1＝可通行）。位元值為 1 代表遮擋為【合理推測】（由 82CDF0 的 `0 = 通過` 推得，未見實際資料）。
