# 原版戰鬥輸入到 socket 的傳送鏈

2026-10-05。僅解析原版韓版 `Tartaros.bin`，未修改或操作遊戲、服務、存檔。本輪 `audit_battle_input_transport.py` 的 9 個完整函式檢查通過。原版怪物自主決策與 P2P 權威來源仍未定位，部署中的 v41 怪物 AI 仍是自製版本。

## 1. 行動封包的組裝

完整控制器更新函式 `5452C0..545B9E` 在 `545829` 設定命令 `000A`，使用共用緩衝區 `FE38D0`、長度 `FE48D0`。

| Offset | 格式 | 已確認內容 |
|---|---|---|
| 0 | WORD | 命令 000A |
| 2 | DWORD | 從 GlobalStatus `F93944` 取得；本輪未確認它的完整語意 |
| 6 起 | 每筆 5 bytes | actor WORD、input WORD、heading BYTE |

先檢查三個主要 actor 槽，再走額外跟隨記錄。前者經控制器 virtual `+48` 產生輸入，後者經 virtual `+44`；已知主要分支有角色模型限制，額外分支是先前核對的跟隨邏輯。**共用封包可帶 actor ID，不代表其輸入生成端就是通用怪物 AI。**

`5471B0..5471D7` 是另一個追加 5-byte row 的 helper，限制組裝後長度不超過 `0x1000`。現有直接呼叫索引只有 `54598B` 一個 caller。

本輪掃描執行區內 `FE38D0`、`FE48D0` 的精確絕對位址引用，候選均落在上述兩個函式內。這不涵蓋別名、緩衝區內部位址、運算後指標或 DLL，所以不能說所有戰鬥輸入都只會走此處。

## 2. 既有連線的完整傳送路徑

已核對的鏈為：

`5452C0 → 8069A0 → 8060D0 → 806060 → 8061A0 / 804A40 → 8068B0 → WSASend`

| 函式 | 完整範圍 | 已確認用途 |
|---|---|---|
| `8069A0` | 至 `8069F5` | network virtual `+10`；依第一參數在 network `+18` map 找連線 |
| `8060D0` | 至 `806190` | 配置／取得封包記錄、複製 payload，呼叫連線佇列加入函式 |
| `806060` | 至 `8060CD` | 在鎖內加入 connection `+A074` 串列、增加 `+A078` 筆數 |
| `8061A0` | 至 `8063DD` | 消費串列記錄，依 `+A02C` 分支呼叫 `807830 / 807A70` 封裝 helper，成功後回收記錄 |
| `804A40` | 至 `804C6F` | 遍歷連線、準備待送資料，經 network virtual `+0C` 傳送緩衝區 |
| `8068B0` | 至 `80699C` | network virtual `+0C`；建置 OVERLAPPED／WSABUF，呼叫 IAT `BD25B8 = WSASend` |
| `806FC0` | 至 `80708F` | network virtual `+24`；鎖定後 shutdown、closesocket 及清理連線 |

`545B6F` 明確傳入連線槽 **0**，並將 `FE38D0` 與實際長度交給 virtual `+10`。先前已核對的初始化將槽 0 指向 8416；這只適用於該初始化路徑，不能將槽 0 泛稱為 P2P 房主。

`8068B0` 的 `WSASend` 返回 `SOCKET_ERROR` 時讀取 `WSAGetLastError`；錯誤 `997 = WSA_IO_PENDING` 作為非同步等待分支。`804A40` 的 virtual `+24` 呼叫則用於傳送失敗／關閉處理，並非新增連線或怪物接管。

封裝 helper 的全部演算法尚未展開；本輪確認的是佇列消費與底層 socket 送出，不宣稱已完整重建加密、所有 frame 格式或所有更新執行緒。

## 3. 對怪物 AI／P2P 的意義

這條已知輸入鏈會把角色／跟隨輸入送到既有連線，由外部回覆共用移動、動作與戰鬥結果封包。`000A` 的傳送方式與已核對的 `000B / 000C / 000D / 000E` 接收方式相接，但請求與回覆的實際配對仍需流量證據。

它沒有提供普通怪物尋敵、選招的本機入口；也沒有在這段鏈中建立額外 peer socket。**這不等於排除其他 client、DLL、別名網路物件、封包中繼或 P2P 通道。** 不應因為找到 `WSASend` 就說已找到第二條 P2P 路徑，它在此是已知傳送管線的底層步驟。

後續應優先找可觀測的普通怪物行動来源：本機是否在收到動作前產生該 actor 的輸入，以及現有網路物件以外是否存在傳送者。繼續從相同三槽角色控制器推測怪物 AI，已不足以增加證據。
