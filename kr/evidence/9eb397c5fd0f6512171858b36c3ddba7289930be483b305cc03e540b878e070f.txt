## 來源與分類規則

REA MCP6.5.0及Ghidra12.1.4已確認可用。新資料來自REA `inspect_pe_resources`（provider rea-pe-resources version1），完整bounded tree包含15個目錄、24個entries、10個payload；type/name/language、file offset、RVA與payload SHA均保留。這不包含image解碼、Windows載入或播放觀察。既有Ghidra overview六個segments與PE raw/virtual欄位互證；沒有為帳務再導入native target。

native body／padding／shared／constant／字串／RTTI使用既有九個readonly分析DB；只讀取原有PE index的422個IAT位置，不重建索引。每個claim保存file offset、VA（可映射時）、range SHA、family、confidence、owner entry（適用時）及source/table/key/Evidence引用。相同range/kind/owner重複只追加provenance；file bytes永不相加重複。

- 強code與data／constant重疊時保留conflict，不用日期或匯入順序裁決。
- 多個code owner重疊只標記待裁決，不自動叫shared code；明確的shared claim才進shared類別。
- 精確字串／結構資料可和較弱vtable extent同時存在。29個被拒slot的來源bytes保留data證據，並明列「只否定slot關係，不全域否定target方法」。
- NOP、LEA、零值與filler只有結合已保存邊界／對齊證據才列padding候選；沒有掃描所有零值就宣稱padding。
- 既有generic unknown範圍不重複加入claim；PE容器本身提供base unknown。特定4F9B00..4F9B15 excluded gap仍有自己的unknown註記。

`.rsrc` raw overhang的168 bytes精確重複`PADDINGXXPADDING`（末尾截斷到對齊大小）。位置同時位於VirtualSize以外／RawSize以內，列padding candidate；不是僅因marker名稱就證明程式永不讀取。其他資料／程式範圍的同名文字不套用此判斷。

RTTI資料來自原台帳的type descriptor、COL、hierarchy、base-array與base-descriptor精確範圍；每段SHA再核對。列出的vtable終止邊界仍保留candidate狀態。422個IAT cells是原檔的pre-loader資料，不是實際runtime DLL函式位址。

## File與虛擬位址分開

另表virtual_regions目前有三項非加總觀察：

- PE `.data` virtual-only tail：`[F8C800,FE83D8)`，375,768 bytes沒有原始file storage；不是runtime dump。
- Ghidra provider的`tdb`：`[FFDFF000,FFE00000)`，沒有PE header/section file mapping；不當作主檔bytes或已觀察到的目標程序記憶體。
- FrameControl全域layout：`[FBAB80,FBABF8)`，120 bytes的static read/write-address觀察，位於上述virtual tail內；不與tail相加，也沒有取得runtime float內容。

因此查FBAB80會同時看到兩個virtual觀察，file_backed=false；不從來源bin補造其目前值。header／section alignment與未mapped檔案位置也不硬套VA。

## 查詢與重建

在workspace執行：

```powershell
python anal/query_kr_regions.py
python anal/query_kr_regions.py --va 0x4b1914
python anal/query_kr_regions.py --va 0x4b18c9
python anal/query_kr_regions.py --va 0x4f9b00
python anal/query_kr_regions.py --va 0xc2a27c
python anal/query_kr_regions.py --offset 0xbe4f58
python anal/query_kr_regions.py --va 0xfbab80
python anal/query_kr_regions.py --category unknown --limit 10
python anal/query_kr_regions.py --claim C000001 --full
```

query會核對主程式、ledger/summary identity及所有claim source／保留快照的SHA，readonly開啟資料庫。預設最多30個claim／reference，輸出matching/truncated欄位；--full保留全部reference，--limit最大500。file offset超界會拒絕。原始module身分與range hash不同欄位保留，不把range hash當主程式SHA。

方法、class及callsite仍用 `python anal/query_kr_evidence.py ...` 的九來源query；它的--address保留歷史個別來源。當前merged file partition使用本輪query_kr_regions.py，不擅改舊封存catalog。

```powershell
python anal/kr-region-ledger-20261023/build_ledger.py
python anal/kr-region-ledger-20261023/verify_ledger.py
```

builder只整理既有PE reader／native／RTTI／resource證據與區間，不反組譯全程式或模擬CPU。sources表、input-provenance.json保存工具／資料來源SHA；REA原始Evidence與Ghidra overview快照保留，來源版本不符時失敗。classification rules另存region_rules.py。

十項驗收檢查全部base interval連續、每段／claim SHA、兩個方向的membership完整性、所有來源不可變性、29個拒絕slot、10個resource payload／目錄資料、特殊unknown/shared/padding位置、virtual與file分離、合成衝突及實際CLI。已核對11,537個claim、16,588個partition；metadata/read-only資料庫均通過integrity_check。這些驗證只證明帳務與來源一致，不證明所有歷史方法邊界或全程式語意正確。
