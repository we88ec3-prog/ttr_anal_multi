## 必須優先套用的更正

上一階段 `kr-persistence-20261023/battle-frame-contexts.json` 把 4B18D4 的 result_EDX 寫為固定 0，REPORT 也沿用了 group4/result0。這個歸納遺漏其他前驅。原始 snapshot／manifest 保留不變，由本輪 [corrections overlay](binding-records.json) 與 [資料庫](bindings.sqlite) 覆蓋其適用範圍。

4B18C7 是 `XOR EDX,EDX`，4B18C9 是 `ADD EAX,B4`，4B18D4 呼叫 7D28E0。case4 在 4B0E50 設 EDX=1、4B0E55 跳入 **4B18C9**；case2 在 4B1181 設 EDX=2、4B1186 亦跳入 **4B18C9**。它們跳過清零，EAX 先從 source actor 的 +15C 取得，因此同一 callsite 會帶不同模型與 result。

| row+4 case | 7D28E0 site | 模型來源 | group ECX | result EDX／INI 欄位 |
|---:|---|---|---|---|
| 0、8 | 4B18A6 | source actor+15C | source motion.v30() 的 AL | 0／NORMAL |
| 0、8 | 4B18D4 | target actor+15C | 4／ATTACKED | 0／NORMAL |
| 4 | 4B0E1D | target actor+15C | target motion.v30() 的 AL | 1／BLOCKED |
| 4 | 4B18D4 | source actor+15C | 4／ATTACKED | 1／BLOCKED |
| 2 | 4B114E | target actor+15C | target motion.v30() 的 AL | 2／CRITICAL |
| 2 | 4B18D4 | source actor+15C | 4／ATTACKED | 2／CRITICAL |

每次呼叫仍受所選 actor 的 model 非 NULL、actor+370 非零、model+AC 非 NULL 等 guard 限制。source 分支被略過也可能繼續執行 target 分支；表格不代表兩者一定同時執行。case0 與 case8 的視覺處理不同，只共享這組 FrameControl 路徑，不將完整行為視為相同。BLOCKED／CRITICAL 對應由實際表索引與鍵名成立，並有 BLOCK／CRITICAL 字串旁證；不承諾原始 enum 名稱。

## 證據、區域與驗證

上游 REA Evidence `ev_b8987634de68d8afdbfbe21ef6d0c113aa044bfb2b23b7544cfacdf7559a4c16`，Ghidra 12.1.4，profile `965552102e88fd60a1ccde827b92cc552a22c4f08ddda16a7fc2bea3c04307c0`。輸入原始 JSON／相關報告／表格與 public MCP driver 保存於 input-snapshots，input-provenance.json 保存來源與 SHA。Python 整理原生 CFG 中選定的六條邊，不重建 CFG、不逐指令模擬。

`[4B1914,4B1938)` 是九個 little-endian DWORD 的 switch target table，依原生 indexed JMP 與檔案 bytes 核對，屬資料，不能算函式 body。`[4B18C7,4B18D9)` 是含多種入站狀態的共享程式尾段，不能另算獨立函式或固定 ABI 的 thunk。4B0640 body 仍為 `[4B0640,4B1914)`，pcode 截斷，只有本輪指定分支語意完成核對。

已保存 8 條有來源的路徑紀錄、9 個已核對 switch 目的地、1 項更正、2 個區域分類，沒有新增有效函式分母。binding-validation.json 已通過 29 個關鍵原始指令／分支、9 個 table entries、SQL integrity 及按 case／callsite／correction 的查詢；其中明確檢查 4B18D4 存在 result 0／1／2 三種輸入，避免再次退化為單一常數。
