# 帳號可使用角色清單測試

使用者說明遊戲可隨時切換固定角色，帳號資料表示可使用哪些角色，不能套用一般 MMO 的獨立角色建立模型。靜態解析亦符合固定編號1..9及每個角色的取得旗標。

0x42 payload 4 bytes 的實際結構為 uint16 command + uint8 + uint8。4a3b80 可由角色 UI 673eaa 呼叫，不能僅憑此封包宣稱點了廣場。0x43 在基本表 offset0x21c 登記為4b1a90，只呼叫4dfd40(6)移除型別6的物件，不足以當進入廣場成功回應。

0xa7 是49129d在GetTickCount差值達0xea60時發送的60秒保活，既有捕獲也每分鐘出現一次；不是廣場按鈕請求。

新增明確選項 --experimental-owned-character：command2追加53-byte記錄，0..41為UTF16 LocalHero及零終止，0x2a uint32等級1、0x2e角色編號1、其他欄位零。4d4150解析此記錄並把角色資料+0x5c設1。command60追加27-byte場景記錄，編號1，外觀裝備零。完整角色統計、裝備與技能仍未實作；合成資料尚未經遊戲實測。

已驗證bootstrap長118、場景長29、codec往返、等級與角色ID欄位。使用Tartaros.local.char-test.exe重新登入後，觀察角色是否可用及廣場點擊後的請求。這是標記帳號可使用角色的實驗，不是建立獨立角色。未知廣場回應不盲目猜測。

實際畫面確認：索瑪頭像由灰色改為彩色，模型成功顯示，廣場按鈕仍無反應。此fixture只確認帳號取得旗標及角色场景顯示有效，不代表完成角色或廣場初始化。

8416紀錄20261002-001551-297500：bootstrap後新增0x26/3-byte請求，另有0xda/4-byte、0xd2/3-byte；0x60後0xf5/2-byte；00:17:11送0x42/4-byte。未取得可確定為廣場進入的額外命令。基本表0x27在4adead註冊4b2af0，解析18-byte列表（len-2）/18，內容建構0x108物件，並非可直接猜測的角色完整統計。0xf6未在已讀的基本初始化表找到註冊，不應以request+1猜回應。

尚待查清廣場UI事件路徑、按鈕前置條件、0xf5及其他未回覆初始化。暫不要求使用者重複同一點擊，也不送未確認場景切換回應。
