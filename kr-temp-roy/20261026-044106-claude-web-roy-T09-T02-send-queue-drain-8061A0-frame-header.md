- payload 混淆（從 6 bytes 之後開始）：
  - `out[0] = in[0] XOR 0xB6`；
  - `out[i] = in[i] XOR in[i-1]`（`i ≥ 1`；迴圈每次處理 2 個位元組，並有奇數尾端單獨處理）。

- 限制：`len+6 ≤ 0x1000`、`len≠0`、`[obj+0x500C]+len+6 ≤ 0x4000`；否則回傳 0。成功後 `[obj+0x500C]`、`[obj+0x5004]` 各加 `len+6`。

## 四、對 0x0A 封包的意義
- 5452C0 組的緩衝（`0x000A` + 4 bytes + N×5 bytes）整體當作 payload：`len = 6+5N`（N=1 → 11）。
- 外框是否為明文（`0x1A68`）或混淆（`0x0BBB`＋檢核值）取決於 `[conn+0xA02C]`；該位元組的寫入者【未知】（已掃描 `+0xA02C` 的存取沒有做；`805D0F`、`806EB4` 等 `+0xA024` 的存取點可能與狀態有關，未讀）。
- 標頭 +2..+5 的 4 bytes 仍然是 payload 的一部分，來源仍【未知】。
