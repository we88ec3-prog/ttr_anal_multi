| `0x004D1710` | CMonster 建構 |
| `0x004C7070` | 共用場景物件建構 |
| `0x004DFF30` | 場景物件登記 |

場景物件欄位：`+0x04` key，`+0x88` 複合 ID，`+0xF4` 為25個元件指標槽，`+0x164～+0x360` 為128個狀態資源槽，`+0x36C` 回收倒數，`+0x38C` 最近事件 ID，`+0x3F0/+0x3F4` 狀態樹。事件8 **未證明**是 OnDeath；命令151 **未證明**直接觸發事件8。

### 狀態資源更新／回收

- `0x004C83C0` 每128槽檢查與清理；`0x004C7DB0` 包裝清理；`0x007BE5F0` 解除底層資源。
- 共用場景物件 vtable `0x00C07554`、`+0x20` 更新方法對應 `0x004C8580`；主場景更新迴圈**仍待定位**。
- `0x007DCFB0` 取得或復用共享資源；`0x007DD1A0` 放入池或清理；`0x007DD1F0` 排空；`0x007B7FD0` / `0x007B8030` 控制延後回收；共用池允許**再次取用**，不是僅待刪除佇列。
- 管理器重要 offset：`+0x44` 延後回收/模式，`+0x5C` 持有計數，`+0x60` 活躍計數，`+0x64` 同步鎖，`+0x7C～+0x80` 復用陣列範圍。
- 底層資源 `0x7C` bytes；wrapper `0x30` bytes，`wrapper+0x2C` 指向資源，vtable `0x00C511CC`。`wrapper+0x20` **不是** `resource+0x20`。
- `0x007BD8D0` 累加 `resource+0x1C += parameter * resource+0x24`；讀取 `resource+0x20` 作完成條件比較；可設定完成旗標 `resource+0x6C`。**不可直接命名進度為動畫時間、`+0x20` 為動畫長度**。
- `0x007A86B0` 活躍資源串列更新/回收，`0x007A87D0` 上層資源更新與派送，`0x007A5DD9` 同輪上層調度，`0x007A68F7` 重設 `resource+0x1C`，`0x0075A6F0` 將資源加入活躍串列。完整控制分支見 T08-093、094。

### 名稱索引、Provider 與 Binding：重要歷史修正

**T08-098 發現型別衝突，T08-099 釐清兩套名稱容器**，這是交接必讀事項：

- `[0x00FE173C]` 是指向 heap 配置之名稱索引的指標；`0x00FE1740` 則是另一棵內嵌名稱樹，`[0x00FE1744]` 哨兵、`[0x00FE1748]` 計數。
- `0x007D7139` 以 `push 0x00FE173C` 傳**位址**給 `0x007B82D0`，寫入內嵌樹中的 `0x8C` bytes 管理物件，其 `+0x00` 為遞增 ID，**不是 vptr**。
- `0x007BDF90` 則先 `mov esi,[0x00FE173C]` 取得 **heap 索引物件**，查詢後由 `node+0x24` 取得多型 Provider。不可把兩棵樹的 `node+0x24` payload 當成同一種物件。
- `0x00719B90` 配置 `0x28` bytes 名稱節點，寫入 `node+0x24` payload；其具體類型由登記路徑決定，**不要**單靠此節點寫入推類別。
- 真正 heap 索引插入者 `0x007DC660`；Provider 登記呼叫點 `0x007D6EC4` / `0x007D6F51`，從 `0x007F15B0` / `0x007F1650` 初始化 `0xB4` bytes 多型物件。
- 主 Provider vtable `0x00C50A8C`：`+0x00=0x007F1620`，`+0x08=0x007F2110`，`+0x0C=0x007F20E0`，`+0x10=0x007F21A0`（配置/初始化並返回 `0xB4` bytes Binding 複本），`+0x18=0x007F23B0`，`+0x1C=0x007F24F0`，`+0x28=0x007F2520`。
- 次級 vptr 位於 `object+0x84`，指向 `0x00C50ABC`；`0x007F25F0` 是將 `this` 減去 `0x84` 後轉向 `0x007F23B0` 的 thunk。
- `0x007BDF90` 依 `item+0x04` 名稱查詢 Provider，以 `vtable+0x10` 得到 Binding，存入 `item+0x08`；`0x007BE0F0` 解除 Binding；`resource+0x74` 表示相關解析/綁定流程狀態。
- `0x007E9BF0` 初始化 Binding `+0x7C`、`+0x80` 為0；`0x007F2320` 設定 `+0x7C`；`0x007F2520` 依全域狀態/`0x00838860` 結果設定 `+0x80`。`0x007BDF40` 只在 `binding+0x80==0` 時派送 `vtable+0x18`；`0x007BDF00` 使用 `vtable+0x20`。`+0x7C` 與 `+0x80` 是兩個獨立旗標。

### 變換、幾何測試與分桶

- 變換結構大小 `0x2C`：translation `+0x00` 三 float；quaternion `+0x0C` 四 float；scale `+0x1C` 三 float；marker `+0x28` DWORD。`0x0077E910` 合成變換；`0x0077E800` / `0x0077E880` 旋轉向量/四元數乘法。
- `0x007BE150` 將子項候選值最大值寫入 `resource+0x20`；尚不可認定為特定物理量。
- `0x00838860` 對六組四浮點係數進行比較，類似六半空間幾何測試；**未證實**一定是相機視錐。`[0x00FB76B0]` 指向 `0x60` bytes、24 floats 的配置。**內容更新者已確認為 `0x00838430`**，由 `0x00799D20` 呼叫；呼叫鏈及實際寫入證據見 T08-118～120。
- `[0x00FB7740]` 指向全域22桶的配置，每桶 `0x2004` bytes（2048個4-byte指標與1個4-byte count），整體配置 `0x2C058` bytes。已確認多個寫入者（`0x007F23B0`、`0x0079CDA8`、`0x007BED5B`、`0x007CD7C9`、`0x007D34EB`、`0x007FECE9` 等），第10桶固定寫入者 `0x007FECE9`。
- **分桶 consumer 的重要界線（T08-104、107、111、125～128）**：`0x007D1310` 的分桶 base 取自 `[EBP+8]` 外部 owner 參數；`0x007D170B～0x007D178F` 會逐筆派送 `entry vtable+0x0C`，後續迴圈清零 **22 個桶的 count**。然而尚未證明實際 owner 等於 `[0x00FB7740]` 的全域 heap 桶；**不能斷言一定是不同實例，也不能斷言就是全域桶 consumer**。`0x00C4FF8C` callback `+0x0C` 指向 `0x007D1310`，`+0x04` 指向單指令 `ret` 的 `0x005F5D10`；兩槽不可混淆（T08-109、113、125）。



### 六平面正常寫入及更新鏈（T08-118～120，穩定結論）

- 兩個已確認直接呼叫入口 `0x00492567`、`0x007BA56E` 均向 `0x00799D20` 傳入字面 handle 位址 `0x00FB76A8`。在 `0x00799D20`，`EBX=[EBP+8]`，`ESI=[EBX+8]=[0x00FB76B0]`，再呼叫 `0x00838430`。
- `0x00838430` 實際寫入 `ESI+0x00～0x5C` 共24個 float；`0x00862C00` 以向量差與外積型計算形成四係數平面，`0x00838800` / `0x00838860` 進行六半空間測試。
- `0x00798DE0` 是 `0x60` bytes **配置及零初始化者**，不可與上述正常內容寫入者混淆。矩陣來源與相機語義仍不可無證據命名；證據詳見 `kr-temp-roy/` 中 T08-118、119、120 原始研究筆記。

### 全域22桶與 callback 生命週期的穩定補充（T08-107、109～115、122、125～128）

- `[0x00FB7740]` 指向 `0x2C058` bytes / 22×`0x2004` 的 heap 桶配置；`0x00798F26～0x00798F78` 初始化配置與 count，`0x007995A6～0x007995BA` 釋放並清空指標。
- `0x007D35F7` 的 `ECX=0x00FB76A8` 呼叫 `0x0079A3C0`，而該函式取 `[ECX+0x98]=[0x00FB7740]`，證明此路徑是**全域桶 producer**；其他多個直接引用亦屬 enqueue；第10桶 count 位移為 `0x16028`。
- `0x00799840` 配置4-byte callback（vptr `0x00C4FF8C`），獨立於 `0x007997A0` 配置並由 `0x00839940` 建構的 `0x470`-byte 核心物件（vptr `0x00C53F44`）。callback `+0x04/+0x08=0x005F5D10` 是直接 `ret`；`+0x0C=0x007D1310` 是按外部 owner 參數處理桶的路徑。
- `0x007D1310` 從 `[EBP+8]` 取得 owner；`0x007D1769～0x007D178D` 最後清零所有22桶的 count，但**全域 owner 身分未獲驗證**。本筆記不宣稱全域桶已有確認 consumer。

## 長期未解決問題（按優先度）

1. `[0x00FB7740]` 全域桶的實際逐筆 consumer 仍未有完整 owner 指標身分證據；需要定位 callback `0x00C4FF8C+0x0C` 的真正分派者，證明其參數與全域桶的關係。`0x007D1310` 的 22 次 count reset 本身尚不足以完成證明（T08-127～128）。
2. 六組幾何平面係數的**數學方向、正規化與場景／相機意義**尚未完全證實；但實際內容寫入者 `0x00838430` **已經定位，不再列為待尋找問題**（T08-118～119）。
3. 場景管理器如何調用共用物件 vtable `0x00C07554+0x20`，以及和 `0x00799D20` 上游調度、資源/渲染派送的時序關係尚未確認。
4. 分桶 entry `vtable+0x0C` 的具體多型實作、物件來源、不同桶類型與 owner 的所有權。
5. Provider / Binding 的繼承結構、引用計數及完整所有權；變換與完成狀態真正用途。
