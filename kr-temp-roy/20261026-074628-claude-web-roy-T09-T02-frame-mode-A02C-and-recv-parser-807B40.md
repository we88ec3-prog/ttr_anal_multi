## 一、`[conn+0xA02C]`（【確認】範圍：以 `+0xA02C` disp32 的直接存取）
- 掃描 `.text` 內 `xx xx 2C A0 00 00` 形式，只有 `805D02`（`c6 86 2c a0 00 00 02`＝寫入）與 `806203`（`8061A0` 內讀取）。
- `805D02` 屬於連線物件初始化段（同一區塊亦設 `[+0xA020]`、`[+0xA024]=0`、`[+0xA028]`、`[+0xA04C]`、`[+0xA030..+0xA03C]`，並配置輸出環 `[+0x501C]`〔`0xFA0` 初始化〕）。
- 因此預設值 `2`。`8061A0` 的判斷是 `==0 → 807A70`，其餘 → `807830`（見上一份）。**靜態上沒有發現把它改為 0 的路徑**（其他間接形式〔如以暫存器偏移組出位址〕未排除）。
- 結論（【確認】範圍內）：本機出站封包（含 5452C0 組的 `0x000A` 封包）預設使用 `807830` → **0x0BBB 外框**。`0x1A68` 外框程式存在但預設路徑不會用到（【推測】可能為舊版／測試模式，未驗）。

## 二、接收端外框解析 `807B40` 之後的函式（`edi＝conn`；緩衝 `conn+4..conn+0x5000`；`ret 4`）（【確認】流程）
- 迴圈：`word len = [p]`（`807BB0`）；`len==0` 或 `len>0x1000` → 失敗（`807E1D`）。
- 取 `word type = [p+2]`（`807BD4`），決定標頭長度 `hdr`（`[esp+0x20]`，預設 4）與旗標：
  | type | hdr | 旗標 |
  | --- | --- | --- |
  | `0x2633` | 8 | `[esp+0x18]=1` |
  | `0x0BBB` | 6 | `[esp+0x1C]=1` |
  | `0x1A68` | 4 | — |
  | `0x22D7` | 4 | — |
  | 其他 | 4 | — |
- 若 `p+hdr+len` 超出已接收長度 → 離開並把殘餘資料搬到緩衝開頭（`807DDA..807E16`，`memmove` `8912F0`）。
- **0x0BBB 路徑**（`807D2C..807D6A`）：`out[0]=in[0]^0xB6`；`out[i]=in[i]^out[i-1]`；`sum = out[0] + Σ out[i]`（16-bit，`add cx,ax`）；與 `word [p+4]` 比較，不符 → 丟棄該封包（跳過處理）。這與 `807830`（送端）互逆，**檢核值＝明文位元組的 16-bit 累加（確認）**。
- **0x2633 路徑**（`807CD2..807D2A`）：`out[0]=in[0]^0x7C`；`out[i]=in[i]^out[i-1]`（此處 `out[i-1]` 為解碼後前一位元組）；之後呼叫 `727190`（`eax=解碼緩衝`、`ecx=len`、`edi=&0x1000`〔輸出上限〕、輸出到 `esp+0x102C`）；`727190` 失敗（回 0）→ 丟棄；成功 → 以其輸出（`push esp+0x102C`）交給 `807E50`。**`727190` 與 .bnd 解析（82F850）所用同一函式**，且在這裡以「輸入 len＋輸出緩衝上限 0x1000」呼叫，與「解壓縮」用法一致，但本次**未讀 `727190` 本體**，仍標【推測】。標頭 +4..+7 的 4 bytes 的用途【未知】。
- **0x1A68／0x22D7／其他**（`807D77..`）：不解碼，直接 `807E50(ptr)`。
- `807E50`：長度 ≤ 0x1000 時把 payload `memcpy` 到池節點 `[edi+8]`、`[edi+4]=len`，回傳 1。
- 其後（`807D7F..807DB2`）：視 `[node+4]` 是否為 0 走 `804310`＋`8076F0` 或 `489920([conn+0xA080])`＋`8040A0`（封包交付；語意【未知】），然後推進指標 `p += hdr + len`，直到剩餘不足 4 bytes。

## 三、對 T09 封包的意義
- 5452C0 的 `0x000A` 封包（`len=6+5N`）經 `807830`：`[len][0x0BBB][checksum]` ＋ 混淆後的 payload；接收端以相同格式解析 S→C 封包，因此 **S→C 位置／移動同步封包也走同一外框**（【推測】；接收端函式本身是通用的）。
- 「0x0A」與 `4409808e…` 的「000B」仍不同命令，**不要合併**。
