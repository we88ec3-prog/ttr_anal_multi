## 一、為何先前找不到分配寫入（【確認】）

- `.text` 中對絕對位址 `0xFAB1D0` 的存取只有：`4DEE6F`（清零）、`4DF022`（清零）、`4CAC3E` / `4DF006` / `545F88` / `56E3E7`（讀）。沒有任何 `mov [0xFAB1D0], reg`。
- 原因：`0xFAB1D0 = 0xFAB130 + 0xA0`。`4DF1A0` 內以 `ebx = [ebp+8]`（holder 指標）存取 `[ebx+0xA0]`，並於 `4DF35F` 寫入：`mov [esi+0xA0], eax`（`esi` 為 holder）。呼叫端傳入 `0xFAB130` 的位置很多（例：`4C1701`、`4BA9C4` 的 `push 0xFAB130`），此處**未**逐一驗證哪個呼叫端呼叫 `4DF1A0`。
- 因此以 `0xFAB1D0` 絕對位址搜尋會漏掉分配者；之後在別的全域上做類似搜尋要同時考慮「全域＝某結構的成員」。
- holder 內相鄰成員（【確認】存取）：`+0x98/+0x9C`（共享指標：物件＋控制區塊）、`+0xA0`（碰撞物件，即 FAB1D0）、`+0xA4`（另一物件，即 FAB1D4）。
