## 2. Client 可證的功能鏈（附 ABI 與反證）

### A. DirectInput Keyboard → logical input → controller（SRC-0364，CLM-COMBAT-0012）

已重新確認 0x6F38A0：device vtable+0x24 以 `push 0x100`、buffer 地址呼叫取得 256 bytes 的 GetDeviceState 路徑，失敗另有重新 acquire 分支；.rdata 的 DIDATAFORMAT 0xBD6994 DWORDs 為 18/10/2/100/100/8B6190（hex）。來源追踪 DIK_Z=0x2C=44 的 SDK 語意；BIN 中 physical 256-byte index 與規則輸入可對照，但 **目前工作 bank 的 Key44→ID13 配對仍依現場設定**，不是任意玩家配置下的無條件事實。

以同一父更新 `0x490FE0` 的合法指令邊界查到 `0x491530` 相位/事件消耗相關呼叫，而 `0x491CB6 call 0x4E0060` 位於後方；在指定 controller/table 路徑下可達戰鬥 tick。這只是一條正常分支上的 **更新順序**，不是所有場景或執行緒的全序，也不保證每次 Z 鍵按壓都發包。必要前提：裝置及 buffer 有效、當前 bank 映射、UI 沒有攔截/改寫、controller gating、持續狀態沒有殘留覆蓋。

### B. SkillMatrix 的有限 4×11 讀取及 gate（SRC-0365，CLM-COMBAT-0013）

`0x54F270` 用 `test al,0xC0` 先處理早退，再以輸入組合選列號（bit0+bit1→column4，bit0+bit2→column5，bit1+bit2→column6，單 bit0→column1，三個bit同時成立先走column4）。`0x81A8E0` 中 `cmp al,4` / `cmp cl,0xB` 守衛讀取，偏移為 `matrix+4+2*(row*11+column)`，傳回 WORD 低16位。它和 `SkillMatrix.xml` loader 的 tier/key/skill 來源相容，**不能因 WORD 值就直接當 animation clip ID**。

`0x5462B4` 將 actor+0x3E8 推入參數、0x5462C3 由模式資料取得 selector、0x5462DD 呼叫 0x54F270。push 順序與保留：arg8 是 modeSelector，argC 是 actor+0x3E8。若 matrix/timer predicate false，但 actor+0x3E8 非零，0x5462F6 仍設通過候選；僅失敗且全 DWORD 為 0 時 `0x546302 and WORD[...],0x8000` 清 lower15。這不是「技能失敗必不發包」。其他 source 的 tick decrement 不被稱為固定毫秒／真實 combo timer。

### C. actor property4 writer、FORCE 字面與 constructor provenance（SRC-0366，CLM-COMBAT-0014）

原生 `0x4CD71C call 0x4C7070` 使用相同 EDI this，`0x4CD728 mov [EDI],0xC07B44` 安裝派生 vptr，`[0xC07B44+0x2C]=0x4CE7F0`。`0x4CE81D movsx ecx,word[EBP+8]`，第 1..30 範圍經索引/跳表，第 4 屬性分支 `0x4CE90A movsx ecx,word[EBP+C]`、`0x4CE914 mov [EBX+0x3E8],ecx`。這是 **signed WORD → DWORD 賦值**，不是按鍵計數器加一。此前基底初始化值=0、派生 setter 和 virtual+0x2C 的同物件來源可追；不能把所有 actor 子類均套用此 setter。

當新值為 1，來源報告指向 actor+0x364 附屬效果及原始 .rdata `0xC07AEC='FORCE'` 字面，已重讀實際 bytes。FORCE 是 Client 字串，沒有證明玩家中文技能名、爆氣/覺醒、motion 播放或者原版 Server 作用。需要後續 property event 與真實 Server/wire 來源。

### D. 6-byte property records 與 actor virtual setter（SRC-0367，CLM-COMBAT-0015）

`0x4AFAF0` 以 argC=length，len小於2時0筆，否則 `0xAAAAAAAB` 乘法 `shr edx,2` 還原 `floor((len−2)/6)`。每個 record 由 `0x4AFB20 movzx edx,WORD[ESI−2]` 取 actor ID（ESI起始 P+4）、再依行取 property/value 兩個 WORD（P+4/P+6 起，每列步長6），成功 actor pointer 的主 vtable+0x2C 傳入 property/value；失敗 log 並繼續。函式 `ret 0xC` 說明三個 stack args；不應以反編譯不完整參數簽名覆蓋此 ABI。payload 只取 floor 筆數，尾端不足一列部分被忽略；不代表任意 len 安全或原始 socket opcode 完整核實。

`0x4ADD50` 安裝 8-byte-slot state dispatcher，其 state key0 可指向此函式。與下一段 **16-byte outer dispatcher** 不得混為同一表，也不因 inner key0 就宣稱 wire opcode=0 有端到端 runtime 證據。

### E. receive queue → header key → 16-byte outer dispatch（SRC-0368，CLM-COMBAT-0016）

`0x804740` drain 得到 queue record 後，record+8 是 payload P、+4 是 length L、+0 另一參數，分類值獨立傳入 callback。當 callback object 經已觀察的 constructor vptr `0xC05AEC`，virtual+0 是 `0x4930E0`。該函式在 `0x4930ED movzx edi,WORD[EAX]` **先讀首WORD，再於 `0x4930F6 test EBX,EBX` 檢查 L==0**；在這個函式內沒有讀之前的 L>=2 guard。這是有界缺口而非已證可利用漏洞；上游是否保證 P/L 合法尚未完成。

分類==2 時 `0x4930E0` 用 callback this+0xB8 的 dispatcher virtual+4；在所見 root layout 中 root+0x148 callback、root+0x200 16-byte-slot dispatcher，`[0xC05B04+4]=0x48AAD0`。`0x48AADA movsx eax,BX` 使 key 取 low WORD 後以每項 16-byte 取 callback/adjustment；active state 的另一路 `0x4FDA30` 才採 8-byte-slot。這僅是一條已確認設置下的 conditional Client receive route，不能宣稱整段真實 Server 對戰回覆、key0與 C2S 000A 因果配對或 Client 全部 frame length 驗證已閉合。

### F. event dispatcher 第二域與 vtable 指標（SRC-0369，CLM-COMBAT-0017）

另一份**不同的 T10-101** 報告解析 `0x5961C0`：除了 0..39 ordinary event IDs，尚有 `0xFDF624` 關聯的 extra ID 容器，`0x59643F call 0x6D4CE0` 與普通 ID `0x59624E` 不在同一個 40-byte 事件迴圈域。實測 .rdata 中等值 `DWORD=0x5961C0` 共 29 個候選（見 JSON 精確地址），不等於 29 個已證實的 class/instance/caller。`0x596430` 是前述 JMP immediate 的中間位置，不能當有效函式起點或 native CALL；沿合法 `0x59643F` 解碼。此處不宣稱 actor motion 或 server command。

### G. three-container teardown 與 actor bit8 回呼（SRC-0371，CLM-COMBAT-0018）

另一份**不同的 T10-102** 研究在 `0x5960B0` 中看到 `0x59610E call 0x596C90`；後者 `0x596C99 add EBX,0xC0` 並設 loop count=3，順序處理 owner+0xC0、+0xD0、+0xE0 之嵌入容器（每次 +0x10）。取節點+0xC 之 object 指標，當 object+0x28 bit8 設起時呼叫該物件 vtable+0xD4，然後處理節點/容器清理。**node+0x21 的 sentinel 判斷不是 object+0x28 的 flag**。這是 local cleanup，不是 attack-cancel、Server ACK 或技能釋放的直接證據；allocator/destructor 的全 CFG 尚未全部接受。

### H. T10-107 為 reconciliation，不增造獨立 native claim（SRC-0370）

此原稿記錄 T10-101、102 同段號但不同 blob 的來源合併，並明列「原先找不到 writer」由較新 101 補上、「event success list」不是 combo queue、「property4」非 000A ACK。將它視作互相指向的歷史導覽，**保留 REGISTERED，不作第八條獨立 native 主張**；即使本次受驗收範圍包括閱讀它，也不假裝此一稿重新跑過所有原生 assembly。

## 4. T01 canonical 去重及跨 Task 限制

- 附近既有主張 `CLM-COMBAT-0001`（phase writer）、`0002`（有條件 C2S 000A）、`0003`（S2C key13 9-byte actor rows）、`0004`（七表 actor+0xB0 state writer）、`0005..0011`（reader/reset、selector、listener、result list）在原 scope **按需引用**，本批不重寫、不覆蓋、不複製為新的證據。上述七項屬不同結構／ABI 或缺口的精確界定，state=PARTIAL。
- 尤其 `0x5961C0` event result list 與 `0x596C90` teardown 是不同 producer/consumer；`0xC07B44+0x2C` property setter 與 `C07554` 基底方法不能合併成每個 actor 共用 setter。高風險布局衝突仍須精確 runtime vptr provenance、所有型別、調用棧。
- 已知 T01 退回 T10-055/056 指令錯位、T10-007 store、T10-026 caller、T10-062/063 reset/reader 混用繼續有效；本批不將錯誤舊位址搬入 newly accepted claims，也不替作者標修復完成。

## 5. 四類剩餘工作與下次明確入口

**Client 待逆向**：direct key44 的 active bank/runtime override、UI consumer 清 phase 與 controller bit persist 全分支、SkillMatrix.xml 真實逐角色值、actor+0x3E8 的完整 writer/reader、param batch 經 state key0 實際接收條件、`0x4930E0` 前置長度檢查、extra event ID 來源、cleanup exception/owner lifetime、具體 motion/queue/cancel。

**Server 待開發**：可相容的應用回覆，但目前 key0 property4 與玩家按 Z 所發 C2S 000A 尚**沒有**相互因果，不能發明原版「攻擊命中/連段/取消秒數」。服務端設計可以先利用限定欄位做候選規格草案，必須標未證與缺欄。

**跨功能待整合**：T02 IOCP/framing/receive queue，T08 actor+3E8 類別/生命週期，T09 motion；先復用既有 exact claim，必要時由 owner 查虛擬派生建構與封包下游。

**待遊玩驗證**：原版 Client 未被執行，未建立 Server，也沒有 capture，因此不能判定輸入可玩、時序一致或普通攻擊可復現。

本研究交付是階段性可用的限定證據。七條索引主張均 PARTIAL，沒有建立任何 FULL_PASS、NATIVE_VERIFIED、SPEC_CONSUMABLE 或 S00 ACCEPTED。
