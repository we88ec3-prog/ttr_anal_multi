## 2. BIN-first 本批獨立實證（可逐 byte 重現）

### 2.1 PE IAT 與欄位身份

以 KR 原始 `Tartaros.bin` 執行 `objdump -p`，不是照抄來源註解：

| PE IAT VA | Native API | 對整合的用途 |
|---|---|---|
| `0xBD20D0` | `SetEvent` | 反證：真正 SetEvent 與下面三個 Interlocked 是不同 Import |
| `0xBD2274` | `GetQueuedCompletionStatus` | IOCP 完成接收 |
| `0xBD2278` | `CreateIoCompletionPort` | IOCP socket associate 候選 |
| `0xBD227C` | `InterlockedDecrement` | `0x806EC4` completion 減 pending |
| `0xBD2280` | `InterlockedExchange` | `0x8065F2` 欄位交換（指標來源須結合外圍） |
| `0xBD2284` | `InterlockedIncrement` | `0x806968`、`0x806981` 增加 pending |
| `0xBD25B8` | `WSASend` | `0x806912` 本地非同步 send 呼叫 |
| `0xBD25BC` | `WSARecv` | 另一側收包路徑，未於本輪做完整收包 CFG |

以下位置的 machine bytes 由程式按真正 `.text` section raw offset 直接比對：

```asm
805DE9: 89 9E B8 A0 00 00             mov [esi+0xA0B8], ebx   ; 初始化
805DEF: 6A 18 89 9E BC A0 00 00       push 0x18; mov [esi+0xA0BC], ebx ; 不同欄位
806961: 81 C6 B8 A0 00 00             add esi, 0xA0B8
806967: 56                            push esi
806968: FF 15 84 22 BD 00             call dword ptr [0xBD2284] ; InterlockedIncrement
80697A: 81 C6 B8 A0 00 00             add esi, 0xA0B8
806981: FF 15 84 22 BD 00             ; 注意本位置前有 push esi，實際 call 於 806981
806E7D: 8D B8 50 A0 00 00             lea edi, [eax+0xA050]
806E83: 3B D7                         cmp edx, edi
806EA1: E8 0A 09 00 00                call 0x8077B0
806EBD: 81 C2 B8 A0 00 00             add edx, 0xA0B8
806EC3: 52                            push edx
806EC4: FF 15 7C 22 BD 00             call dword ptr [0xBD227C] ; InterlockedDecrement
```

**本批解釋**：`Conn+A0B8` 在已確認的 send post/completion 路徑是原生原子 pending-I/O 計數；`Conn+A0BC` 不同欄位；`0xA050` 是出站 OVERLAPPED identity，`0xA064` 才是傳 `WSASend` 的 WSABUF 起點。歷史 T03-6 把 `+A050` 當 WSABUF、`+A0B8` 當 OVERLAPPED 的文字 **REFUTED（先前 T01 已正式登記 CLM-NET-0013）**。不能把任何 `Interlocked*` 稱作 `SetEvent`，不能宣稱每條錯誤、cancel、重連路徑都已使 pending 計數平衡。

`0x8068B0` 還需分清 call stack 參數：`0x8068DE lea eax,[esi+A050]`，`0x8068F3 push eax` 傳最後的 OVERLAPPED；`0x8068F7 lea ecx,[eax+14]`、`0x806909 push ecx` 傳 WSABUF (`+A064`)；`0x806912 call [BD25B8]`；零長、停止 flag、`WSA_IO_PENDING=997` 與 sync success 邊界由來源 E48／T16-97 描述，本批只定向驗 import/bytes，不聲稱捕獲網路的封包。

### 2.2 另一重大更正：`0x49B070` 不執行 active map erase

```asm
49B070: A1 58 A8 FB 00          mov eax,[0xFBA858]
49B075: 85 C0                   test eax,eax
49B077: 75 1D                   jne 0x49B096
49B079: 39 05 5C A8 FB 00       cmp [0xFBA85C],eax
49B081: E8 DA FE FF FF          call 0x49AF60
49B08C: E8 6F FF FF FF          call 0x49B000
49B091: A1 58 A8 FB 00          mov eax,[0xFBA858]
49B096: C3                      ret
80703E: E8 2D 40 C9 FF          call 0x49B070
807043: 8B F8                   mov edi,eax
807045: E8 36 EA FF FF          call 0x805A80
```

`0x49B070` 直接可見的兩種初始化分支只取回 singleton pool 指標；不以 Conn 指標進行 active key-map erase。**E48 的「49B070 是 map detach」已被 E49/E50 更正，保留舊原稿但在跨 Task canonical 採用時不可再引用此錯誤說法。** `0x805A80` 是另一函式、同一路徑的 pool+0x28 list tracking；不能由 close/recycle 推認 manager map 同步除名。

### 2.3 真正的條件式 tree erase／再插入鏈

由 `0x806C80` 附近可見：

```asm
806C9E: E8 1D CC 03 00          call 0x8438C0          ; manager tree lookup
806CAA: 74 0C                   je 0x806CB8            ; end/sentinel skip erase
806CB3: E8 D8 FB FA FF          call 0x7B6890          ; tree erase helper
806CC7: E8 54 82 D7 FF          call 0x57EF20          ; new-node allocation/helper
806CD2: E8 79 7B D7 FF          call 0x57E850          ; map insert/helper
```

`0x7B6890` 實際函式體可見 `0x7B68E9` 讀 tree owner、`0x7B68F4–0x7B6904` 重接 parent/child link。**這能補強 E50 描述的 tree node erase 候選**，但不能由靜態片段證明被回收的是哪個舊 Conn 的全部引用、是否仍有 pending IO 或每次重連都觸發；須補全 alias 與錯誤/取消路径 CFG。該 helper 的 tree 角色可採 PARTIAL；同 key 全生命週期尚非 FULL-PASS。

### 2.4 Pool+0x28 與 Pool+0x48 不可混同

`0x805B40` 的 native 迴圈先取 `Pool+0x28` 的 linked list，`0x805B7B` 使 `Pool+0x2C--`；其後 `0x805B88` 從 `Pool+0x48` 取另一串列，`0x805BA6` 讀 `Conn+0xA0B8` 後走 gated recycle。這與來源 E49/E50 的「雙追蹤／回收狀態」方向一致；**仍未做所有 producer、writer、iterator/erase 路徑與 race 整體驗收**。
