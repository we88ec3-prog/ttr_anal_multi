日期：2026-11-18。這份進度以固定原版資料與程式分析為依據；本輪沒有實際登入遊戲或完成通關測試。

### 這輪最重要的新發現

資源索引檔就像遊戲的「素材地址簿」。原程式能成功開啟這本地址簿，**不代表裡面列得完整**；某些空內容仍會讓程式跳過重新搜尋素材。這能解釋為什麼「素材檔案放著、包也宣告了」仍不等於角色或地圖一定載入成功。本輪將讀取格式、重複名稱與重新搜尋的條件做成可檢查的契約；真正選中哪份檔案，仍要同版本索引或實際安裝目錄資料才能決定。[P0 證據](p0-selection/)

**P0 判定：指令與收尾規則已有可採用的分析；素材齊備與實際選檔尚未過關。**

### 玩家最容易看見的差別

目前 **Server 重建候選採用的 Q119 編排**，前三個戰鬥節點與第四個節點的出口建立時機不同：前三個在清完敵群後建立出口；第四個先放一個關著的出口，清完後再打開。Server 若把兩者寫成同一種處理，可能出現「怪都清了，門卻不出現」或「門提前能走」的問題。這是待開發驗收的候選政策，尚不是已在原版實際觀察的遊玩結果。[旅程契約](../MEF-P0-P1-master-continuation-20261117/journey-families/contracts.json)

本輪另外找到對話框的實際介面檔 `UI/Component/TalkBox_Scenario_Panel.FTC`。它能幫助補齊對話框載入與子元件的分析；但目前尚未取得該檔內容，不能據此說「所有一般場景事件已能自動運作」。[P1 證據](p1-entry/)

**P1 判定：完整任務旅程及七種功能的資料分析已有成果；一般背景腳本入口、任意怪物結果到原腳本的連接仍未閉合，Server 整合與實際遊玩也尚待驗收。**

## Server 接下來可以直接做的事情

依序採用內容與資源檢查、任務／劇情排程、權威戰鬥與清組、出口狀態、結算與回城、任務／背包／貨幣保存。這些是 Server 開發需求，無須等官方 MEF 格式全部破解才開始。既有實作應由目前 owner 對照採用，這份研究沒有把尚未審查的 Server 功能一律判成不存在。[需求與驗收](SERVER-REQUIREMENTS.md)

先依專案既有順序完成登入、創角、新手教學與進入廣場的正常流程。接續的 MEF 旅程驗收目標是：**正常接下 Q119，完成全部節點，得到一次正確結算，回城後可以走動與對話，任務與獎勵正確保存，符合等級與 NPC 條件時能接 Q120。** 原版背景腳本與官方 MEF 相容繼續獨立補證。
