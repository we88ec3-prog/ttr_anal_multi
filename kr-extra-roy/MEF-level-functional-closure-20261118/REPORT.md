# 關卡 MEF 完整功能分析：整合結論

本輪採使用者已確定的方向：**MEF屬於Server開發，Server供應內容，能以MEF完成的先以MEF完成。** 研究對象是能實作的玩法，不以復原官方MEF為目標；Server執行的規則資料化也在範圍內。本包完成20類關卡功能的來源與接口盤點，並提供可重跑的實際內容分析。日期2026-11-18，baseline `09799b117f01e577be56dee3e909e1cde25b855f`。[方向](../MEF-CURRENT-DIRECTION.md)、[功能總表](feature-status.json)

## 1. 玩家的一場關卡，應由哪些 MEF 工作接起來

| 遊玩階段 | MEF工作與可沿用能力 | 交接的可靠依據 |
|---|---|---|
| 進場 | 選圖、出生點、敵群、入場演出、是否保留角色狀態 | 選定內容版本，現有loading／actor／points／ready狀態 |
| 戰鬥 | 初始群、定時與順序增援、HP門檻、頭目、陷阱、巡邏 | 權威實體與已接受戰鬥變更，Client本地動作／顯示 |
| 機關 | 進區、連續站圈、按Z、一次旗標、障礙、分支出口 | 當前instance／node／位置／存活／ALL條件 |
| 清場 | 個別波完成、必要波全部完成、倒地移除、劇情閘門 | 不以畫面暫時沒怪或物件停止移動代替完整清場 |
| 開門與換圖 | 已提交旗標投影到當代完整點集；合法出口指向目的節點 | 同一generation的點／排送；每個出口獨立授權 |
| 結果與返回 | 擊倒經驗、清場獎勵、任務完成、招募、離隊／復活 | 各自現有服務與交易收據；演出回報只支持其本來流程 |

這些工作不需要全部塞進同一個Client腳本。現有scenario JSON已能表達大量MEF規則，可直接沿用；採新格式才需要新的轉接。Client已有的有限Q、點效果、移動、圖片、攝影機與聲音可以承接適合的本地演出；某個普通場景常駐Lua接口未閉合，不阻擋Server MEF或有限演出路線。[規則](rules-waves/report.md)、[交接](finite-handoff/report.md)、[前輪能力範圍](../MEF-server-provided-capabilities-20261118/REPORT.md)

## 2. 本輪真正新增的證據

### 2.1 從實際配置查完整規則圖

67份檔案、86個定義出現、399個節點出現，全數通過目前schema；本輪的有限圖、唯一key、旗標來源、分支保證交集與清場前後固定點稽核未發現所列結構問題。內容包含868個初始怪物條目、27個額外波、16個signals、45個替代出口。

這是有明示前提的可完成安排分析：假設敵人可打倒、區域／機關可到達、時計可進展；不是實際Server loader或逐tick模擬。跨層必須再看地形，所以不能把前述PASS寫成全部可玩。[完整稽核](rules-waves/content-audit.json)、[方法與限制](rules-waves/report.md)

### 2.2 實際地形查出內容差額，並給出可採用候選

118個MapID對到74個BND，1763個配置中心中1753可站立且與出生點同四鄰分量。十個不合格點全在舊 `branch-example`：2個出生點、3個怪物點、5個出口。其餘66檔的1750個中心在本次靜態政策下未見同類問題。以上只證Server所用二維靜態格的中心可走與四鄰連通，不證完整三維地形、角色尺寸或Client動態碰撞。

本輪已具體提供四節點13個中心的候選修正：全部中心可走／連通、出生到各中心直線採樣通過、5個出口圓採樣通過。未改既有來源。要採用時仍保持原map／key／分支及怪物身分，並以選定發行版本進現有正常流程驗收。[地形證據](space-mechanisms/spatial-evidence.json)、[修正候選](space-mechanisms/content-remediation.json)

Q119三個barrier候選雖可擋直走，關閉時仍有18步繞路到出口。這代表**局部障礙**，並不代表出口授權失效；出口仍受清場／旗標管制。若玩法要一扇真的封住通道的門，就要選真正瓶頸，驗證關閉時斷路、必要戰鬥／機關留在可達側、開啟後有路，再配合門模型和Client碰撞；不能只發一個開門光效。[繞路與四個consumer](space-mechanisms/report.md)

### 2.3 倒數、波次與清場順序已接到真實規則

同一次有效更新先處理定時波，再檢查順序波；前者新生成的活怪會讓後者繼續等聚合清空。清波與血量旗標早於整場清場；尚未出場的必要波不能因畫面空場就被略過。

本輪整理六種不同的計時原點／派送語意，並不代表六個實體時鐘。清場後倒數在劇情及Portal提交後首次有效位置才起算；節點倒數從開放戰鬥起算，清場劇情中的時間仍經過，派送則等待合格更新。占點、陷阱又有出區重設、不追補等規則。因此優化期限排程必須保留原時計與派送phase，不能同秒數換成 `Q.wait` 就稱等價。[規則契約](rules-waves/rule-contracts.json)、[優化等價要求](rules-waves/optimization-contracts.json)、[機關時計](space-mechanisms/report.md)

### 2.4 重播不再只看 Server 的「本次是否發過」

新沿正常quest0 End追到 `CSL.scn` 寫出4-byte scene key，Q manager初始化又讀回同一集合。保存／讀回成功時，已看紀錄可跨Client重啟。特定flag／mode／quest0／seen條件成立時，原生Start直接送003F並跳過內容。

因此舊「一次／Client epoch」只能限制Server派送次數，不能保證Client必播；收到003F也不能證明callback或開門setter曾執行。非零quest跳過這個seen檢查，但End仍有真實確認回值條件。這不是全面禁止有限MEF，而是把可跳過演出、必須播放內容、業務狀態三者接到各自真實依據。[9個原件窗口](finite-handoff/native-evidence.json)、[完整重播政策](finite-handoff/report.md)

### 2.5 Q119 的具體清場與結果交接

Q119作者節點4對Map635、原來源sourceNode1、出口category0/key4。清場scene是Quest119/scene4；這些4不是同一種ID。三份選定配置是替代版本，不自動混合。

既有清場過程在敵人移除排送與完整清場門檻成立後提交敘事、播放清場演出；核對演出完成再提交、重建同圖，重新發完整0027。這個新快照應由已提交MEF旗標產生。重建前的本地setter可能被覆蓋；重建後點已開則額外setter沒有狀態變化。沒有必要為一個開關強加新Q run。需要多步新演出時，重建後hook才列為選用的Server MEF開發項目。[實際配置投影](finite-handoff/content-projection.json)、[完整結果生命週期](outcomes-continuity/report.md)

新補證也識別了Scenario結果後的 `CEmployNewCharacter` 招募視窗：所選按鈕在非教學分支送2-byte 0033，教學分支另走本機旗標／關窗。這閉合了特定後續視窗，沒有把它擴大成所有取消鍵或通關確認。[原件結果補證](outcomes-continuity/native-proof.md)

## 4. 優化應按可減少的工作分類

**第一類是減少Server實際計算。** 按事件與旗標索引只重算相關規則；以有效HP／生成變更更新每波彙總；保留各計時種類原點與phase的期限排程；已完成一次性區域退訂；共用不可變內容計畫、BND底圖與合法路徑快取。這些改變可少掃描、少解碼、少尋路，但仍需要實作和量測。[規則優化](rules-waves/optimization-contracts.json)、[空間優化](space-mechanisms/spatial-contracts.json)

**第二類是把可行的本地工作交給Client MEF。** 多個本地等待、動畫、鏡頭或特效可以比較一次有限內容派送的收益。純單點狀態的0048是6個應用層bytes；quest0有限插播至少0047/003F/00EB共16個，還可能需要點同步。不能因叫MEF就假定流量更低，也不能把Client本來就在做的動畫再算一次節省。[有限內容成本](finite-handoff/report.md)

**第三類是讓Server規則資料化。** 目前JSON／typed規則已是Server MEF的一部分，可減少散落的硬編碼，方便編排關卡。它不等於CPU搬到Client；維持這個區別才能公平比較實際收益。九項具體順序與接受條件見[優化計畫](optimization-plan.json)。

## 5. 下一輪分析方向

先收斂一份可發布的關卡配置，使用本輪已核的地圖、點位、波次和結果服務。選現有Q119或功能lab時，明確挑一份變體；不可默默把不同候選中的屏障、陷阱、延遲和延續全部合併。

接著沿最需要的接口追：真正物理門要具體模型／動作／碰撞的同一生命週期；主線倒地退出要精確按鈕→請求→現有返回服務；Client常駐戰鬥MEF要選定controller、tick、事件回報與取消，而不是重新搜尋官方檔名。更豐富的隨機路線、循環、道具條件與中途永久checkpoint應按玩家需求新增typed條件和保存政策。[精確待開發項目](DEVELOPMENT-PLAN.md)、[前輪能力接口](../MEF-server-provided-capabilities-20261118/DEVELOPMENT-PLAN.md)
