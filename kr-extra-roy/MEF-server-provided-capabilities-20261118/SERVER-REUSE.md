# 已有 MEF／Server 成果與本輪接入差額

**既有 Server 資料化／事件引擎屬於本任務的 MEF 開發成果。** 本輪不因它使用自有 schema、在 Server 執行，或未還原官方 `.mef` 就把進度歸零。下表復用目前研究基線中的正式開發紀錄；這是對既有紀錄的採用，不是本輪重跑 Server 或新增人測。

主要來源：[關卡／MEF 功能完成追蹤](../../governance/MEF-FUNCTIONAL-COMPLETION.md)、[共用事件引擎](../../design/runtime-content/STORY-EVENT-ENGINE-CANDIDATE.md)、[AI 設定接線](../../design/runtime-content/STORY-AI-PROFILE-CANDIDATE.md)。後兩篇的早期段落保留歷史狀態，遇到接續狀態以目前功能追蹤及被引用的後續專項為準。這些來源原已說明不以官方樣本作功能前置；本輪修正的是後來 extra 研究的優先序及能力解讀。

## 1. 不重造已有的引擎和底層

| 玩家功能 | 已有可復用成果 | 本輪 MEF 開發應新增／整合的差額 |
|---|---|---|
| 進關後依內容推進 | 有版本與 SHA 的 Scenario／MonsterBehavior、每實例事件狀態、Entry／GroupCleared／InteractZ、終點與結果提交；後續主線已有共用事件引擎 | 把新 MEF 規則編譯／綁定到同一模型；Client 可執行動作另產出相容內容。無需先另建第二套事件引擎 |
| 生怪與增援 | 逐出生 profile、順序／定時／區域波次、指定波清／血量旗標、跨波保留角色資源與冷卻 | 判斷哪些用途可由本地 world 生成承擔；共享怪物仍以已接 world adapter 為起點。必要 ID 與事件橋具體列出 |
| 怪物移動和出招 | 共用 AI 參數、追擊／回位、巡邏、輪替選招及個別冷卻；Client 固定路段已有單次目標與 Server 待機排程 | 復用 native 逐 frame 移動／動畫；減少不必要的重複指令。是否能把敵方決策本身移至 Client，依新世界鏈證據判斷，不能僅把 JSON 改名就算完成 |
| 清場後開出口／機關 | 點預先登記、勝利後更新、旗標、條件出口、清場延遲、屏障與占點等已有內容契約或實作 | 本地已知條件可直接 setter；Server MEF 收群清後亦可用一次 `0047` 選 finite 內容，Client 自行演出再開門，不需通用事件橋；單項開點則沿必要 `0048` adapter |
| NPC／商店／銀行／裝備 | 市場外部設定、共用交易與資產更新、銀行存提款及部分裝備能力／外觀接線 | MEF 定義可用服務、條件與內容；接既有請求／結果。外觀／UI 操作與資產變更仍依實際 consumer 區分 |
| 任務結算與成長 | 指定主線正常終點／返回流程、版本化完成事件、經驗／錢包／進度同交易提交；已知發布封包 | 用 MEF 的已滿足條件與獎勵規則驅動既有結算入口；別把 Q 結束回報直接當通關。新增任務與重複挑戰政策按內容擴充 |
| 重新登入後繼續 | 已有主線游標、帳號角色成長／資產、獎勵帳本等保存；未完成副本依既定政策重新開始 | 新 MEF 規則版本與已完成里程碑接同一存檔；若產品要求中途繼續，才另設可恢復 checkpoint，不自行改成保存任意 Lua VM |

既有內容引擎降低逐關硬編碼，Client native 更新承擔本地 frame 工作；兩者應各自計入成果。可下放多少新的 Server 計時與命令，仍須對所選內容比較，見 [負擔量測](LOAD-REDUCTION.md)。

## 2. 既有驗證狀態照原範圍保留

目前功能追蹤記載順序／定時／區域增援、部分追擊／回位與固定路段曾有人測；條件出口、手動互動、部分巡邏／投射物視覺、正式關卡幾何、NPC 交易等尚有各自待測項。不能把「引擎已實作」升成「每關都可玩」，也不能因有待測項抹掉已有驗證。

本輪僅重跑分析包的身份、原件有界證據及契約一致性核對；沒有重跑那些 Server 測試、採集新的遊戲畫面或宣告待測項通過。現行測試排程維持專案既定正流程。

## 3. 結算來源優先序

[經驗／錢包發布與保存](../../governance/client-variants/20261108-mainline-progression/experience-publication.md) 提供已接的 `005C`、`0034`、`006F`、`002C` 及同交易結算；該文件早期曾保留 QuestInfo `RewardsEtc type 3` 未知。

[後續技能熟練度證據](../../design/runtime-content/SKILL-PRACTICE-PROTOCOL.md) 已補上 type 3 的技能熟練度來源與結果 UI。應使用後續精確證據修正早期未解，不能繼續把 type 3 值 40 當成未知獎勵類型。具體欄位、結果路徑、現有保存與新 MEF 規則的接入契約見 [NPC／進度報告](npc-progression/report.md)。數值來源與「發給誰、何時發、倍率、是否可重領」的自有規則仍分開記錄。

## 4. 需求移交方式

本包的優先序是既有需求的分析與接入建議，不新建正式 REQ／RR 台帳。S00 應依當前需求與已實作 adapter 去重，將真正差額納入原有工作線。所有七項使用者指定功能都屬 MEF／Server 開發或整合；「需保存／同步」不構成排除 MEF 的理由。
