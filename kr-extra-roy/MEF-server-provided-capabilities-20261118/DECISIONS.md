# 本輪方向決策與歷史分類修正

本頁記錄使用者 2026-11-18 的明確要求及本輪設計判斷；不是官方格式、正式 S00 ADR 接受紀錄或新的平行需求台帳。工作分支 `extra/roy1`；研究基線 `60c1c1a5dc7a73902d9dbb50361d5148e8b30058`，已核對 main `5ed4833b805949fabe260aea77e3fe0fd8e86bfa`。共用指示及已發布來源的精確身份收於本包 `source-manifest.json`。

## 1. MEF 是 Server 開發的內容與規則層

使用者已確定 Server 提供 MEF。這是本次架構前提，研究工作是找出它能承擔哪些內容、運算與流程，以及如何使用原版 Client 已有的能力。

因此「生怪是 Server 開發需求」應展開成：MEF 定義生怪時機、位置、模型與波次；可由 Client 執行的部分下放；剩餘身分、共同世界狀態與具體接口由相容 adapter 接上。不能把整項變成「Server 寫死，MEF 不管」。戰鬥、群清、出口、結算、獎勵與保存依同一方法拆解。

## 2. 兩種 MEF 執行位置都在開發範圍

| 執行位置 | 適合放的工作 | 可以得到的收益 | 不能直接推出的事 |
|---|---|---|---|
| Client 的既有 Lua／native 執行鏈 | 有限時間線、鏡頭／角色／聲音／UI、已證的本地條件、既有互動點；符合接口的本地世界操作 | Server 不必替內容中的每一步安排計時與命令；native 已有更新鏈可持續工作 | 有 native 動作不代表全部敵對 AI／HP 判定／通用事件已接入 Lua；本輪未量測 CPU 節省 |
| Server 的自有 MEF 規則執行器 | 波次與任務狀態機、成功條件、掉落／獎勵表、進度轉移、結果如何保存的規則 | 多關卡共用一套規則引擎，減少每關 if／switch 與重複維護；可採事件到達時才求值 | 規則仍在 Server 求值，不能算已把同一工作量移至 Client；這個自有執行器不冒充原 Client loader |
| Server 的既有 adapter | 把已知事件餵給 MEF、把 MEF 動作轉成既有封包／交易、把完成結果持久化與發布 | 內容規則和已有底層接線可復用；只保留所選 profile 需要的跨端邊界 | adapter 不是「MEF 不處理玩法」的理由；既有實作也不等於新 MEF 已整合 |

同一發布品可以產出 Client 相容內容與 Server 規則兩份投影，共享內容版本及邏輯節點。這是建議的自有內容建置方式；原 Client 不會自行讀任意新的 JSON schema，必須經已證 loader 與現有表示方式載入。

## 3. 不再把官方 MEF 復原列為目的

官方 `.mef` 首次 reader、container／grammar 搜尋保留為歷史證據，退出本輪目標。自有內容可以使用已證的 `.seq` Lua 文字路徑、Tutorial 入口及 Server 端規則。副檔名不是能力判準；不得為了叫 MEF 就宣稱原 Client 能直接解析新設計的格式。

`NOT_NATIVE_MEF` 只表示「這是我們自行設計的內容／schema，未冒稱官方來源」。它不是完成度扣分，更不能導出「不算 MEF 開發」。本輪完成判準是能力和接口是否可實作、如何減少 Server 工作，與缺官方檔案無關。

## 4. 缺口必須約束到實際依賴

| 舊分類／容易誤解的說法 | 本輪正確處理 |
|---|---|
| P2 缺官方 MEF，所以整體 MEF 未完成 | 官方復原退出目標；保留其歷史未證狀態，不再阻塞自有內容 |
| 普通場景 B 未閉合，所以新 MEF 都不能跑 | 有限 Q 與 Tutorial 已有可分析的入口／pump；B 僅影響普通場景保持原操控的常駐 Lua profile |
| 缺 Field.stp／特定 Q119 資源，所以所有內容未就緒 | 只要求實際發布品依賴的模型、地圖、UI 與資源選取；不使用它們的內容可獨立推進 |
| Server 決定生怪、群清或獎勵，所以排除 MEF | 規則先放 MEF；Client 能執行的下放，Server MEF 規則及 adapter 承擔其餘可實作部分 |
| `lb.CreateObjectEx` 沒有 ID 回值，所以沒有生怪能力 | 本地世界生成能力與跨端身分配對是兩個問題；需要哪個就補哪個接口 |
| 已畫出傷害數字／收到 Q 結束，所以可結算 | 原生呈現、事件完成、HP／群清、任務完成與存檔各有實際 consumer；不得拿非結果回報代替 |
| 新 MEF 尚未交付，所以現有 Server 資產與任務功能都缺 | 對照當前已發布實作與收據，復用已有底層；只列新內容接入差額 |

## 5. 本輪交付與驗證邊界

交付的是重新分析、原生增量證據、內容作者契約、功能全表、Server／Client 分工及開發順序。分析可完成，不等於新內容已發布或可玩；每個缺口在報告中指出需要的新接口或整合工作。

本輪沒有改動或執行原始 BIN、EXE、STP、Lua、Server 或資料庫；沒有修改正式 RR、Task owner、T01 認定與 S00 規格狀態。保留既定正常登入／創角／教學／廣場的實機優先序，未重啟暫緩測試。這些驗證邊界來自既有專案工作規則，並不減少 MEF 的開發範圍。
