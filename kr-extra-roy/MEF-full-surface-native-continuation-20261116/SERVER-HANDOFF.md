# Server／內容開發交接：按執行壽命擴充相容腳本能力

沿用 REQ-0019／REQ-0021 的既有脈絡，交 S00 去重；不新增正式REQ、RR、owner或驗收狀態。來源見[完整研究](REPORT.md)及[SOURCES](SOURCES.md)。A1 v1原規格不變。本文件不是新增可部署腳本，不授權修改Client或遊戲資源。

## 1. 不必把每個效果都改成背景 Lua

內容工具／Server配置分為三類：

| 類別 | 可採用範圍 | 開發契約 |
|---|---|---|
| 即時本地修改 | 既有point狀態、已知對象上的設定 | 一次合法呼叫、正確typed key；沒有成功ACK的接口不能靠回傳值猜命中 |
| 啟動後native續行 | 本輪Q actor步進／動畫／draw、Fade與Sepia | 必須保存owner、依賴、同場景限制、停止與清理政策；End不是全部清理 |
| 等待／分支／權威結果 | 多階段腳本、世界事件、服務和任務規則 | 合法pump／callback仍須舉證；Server自行提供權威判定及相容回覆 |

第二類可在**初始允許有限插播**的前提下研究。它沒有消除初始Q接管，不能標成B不中斷操控完成，也沒有回復已End的Lua task。

## 2. 按玩家功能列 Server 待開發

| 工作項 | Client已知契約 | Server／內容開發要求 | 驗收與未知界線 |
|---|---|---|---|
| 內容建置及發布 | SceneList鍵→seq→prepass／正式VM；121正式名稱有各自ABI | 同一來源產生雙階段依賴；固定內容hash、合法鍵、call arity及型別 | 自訂定義標NOT_NATIVE_MEF，不把新schema塞入原wire；發布仍依現行授權 |
| 有限啟動與收尾 | 0047、003F、00EB各有不同意義；A1有單次政策 | 同玩家排他、合法場景、過期訊息抑制、可靠queue與失敗狀態 | 003F不是功能成功；00EB排送不是控制已恢復；沒有run token可虛構 |
| 演出角色續行 | Q actor可在End後繼續native步進／動畫／繪製 | 記錄Q slot、model/action、建立內容版本、目前場景、清理入口與所有權 | 不是world EntityId；不可拿來直接替代網路怪、傷害或掉落 |
| 角色回收 | DeleteObject是stub，DeleteAllObject是全部Q tree；inactive Stop不走主要bulk | 發布前保證有合法且不誤刪其他內容的清理政策；只准互斥owner | 不猜自動消失、不以到點當已回收；跨圖／下一次Q另需對帳 |
| 淡幕／色調 | Fade及Sepia native可在Q inactive後推進 | 正整數count；標記共享遮罩／色調owner、自然結束或顯式clear | FadeOut到255不自動停止；Fade.End(0)仍可能遮畫面；不是毫秒timer |

| 權威戰鬥與共享狀態 | Client本地視覺動作不證明命中/HP/清組 | Server通關、怪物/玩家實體、同步、資產、獎勵及保存 | 不要求還原官方Server內部；未知Client wire另列逆向 |
| 玩法與插播時序 | A初始有Q/輸入/UI副作用 | 決定插播時玩家／敵人攻擊和共享事件的相容協調政策 | 這是Server設計，不宣稱Client自動暫停Server戰鬥 |

## 3. 建議實作順序與准入條件

先保持A1一次切點作基準，完成既定資料綁定與授權驗收；它仍不含本輪新效果。下一個可獨立縮小的內容是「正向啟動後會自然回到透明的淡入」，再評估演出角色走位；兩者都不需要先解普通死亡／清組觀察，亦不需將全部戰鬥交給腳本。

每個新內容必須明列：適用Mission／Scenario、首次入口、資源版本、typed參數、依賴準備、是否需要Lua等待、native owner、結束predicate、恢復／清理方式、Server回報責任。沒有可信資料的model／位置／slot／鍵不得猜填。候選新內容鍵未分配；不要直接重用A1單次鍵測不同內容。

演出角色續行目前只完成有界靜態功能鏈，尚未形成可發布最小規格。直到它的正常結束後清理與同玩家互斥關係明確前，不應把保留物件直接加入正式流程。

## 4. 正常路徑驗收規畫（本輪未執行）

同一普通場景與合法內容 → 相容入口短暫接納 → 正式callback啟動選定native操作 → End及適用收尾 → 玩家控制按既有流程恢復 → native效果仍按已證狀態機推進 → 終點／透明／清理正確 → Server權威進度一致。

記錄資源hash、場景／typed key、選定內容、實際封包與畫面/輸入。不得把觀測不到的Client內部欄位寫成Server實際收到。沒有取消／故障測試授權時只保留相關測試契約，不擅自啟動遊戲或完整Server行為測試。

## 5. 剩餘責任分類

**Client待逆向：**官方MEF first-loader/grammar、B首次無接管入口、超出已證環境的typed事件與query。**Server待開發：**上述發布、排程協調、通關／服務／資產／保存。**跨功能待整合：**各owner生命周期與新內容／清理入口。**待遊玩驗證：**正常流程真實輸入、畫面、結果及雙端一致性。四類不互相冒充完成。
