**來源：**本次 ChatGPT 對話中使用者明確提出，依 S00 `PLAYER_ADMIN_REQUEST`／`requester_role=ADMINISTRATOR` 以去敏方式登錄。此為產品需求來源證明，**不是歷史 Server 程式、原生 Client 封包、正式設計批准或執行授權**。不記錄使用者身分、真實帳密或個人資訊。

## 原始需求（保留用語）

> 使用者需求幫我規劃WEB端後台，目前第一個後臺需求是新增玩家帳號/停權帳號N天/永久/解封，規劃完後請幫我上git

## 拆分理由與範圍

- **REQ-0006（後台進入與操作安全）**：由「WEB端後台」推導必要的管理員身分驗證、操作權限與稽核，屬**實作安全必要條件／方案建議**；使用者沒有指定登入方式、角色組合、MFA 或稽核保留期限，待維護者決策。
- **REQ-0007（新增玩家帳號）**：使用者明確提出的新增帳號流程，結果是可持久化、可被 Server-owned authentication 尋得的帳號；不能自動建立角色，也不是原版 Client 註冊操作。
- **REQ-0008（停權與解封）**：使用者明確提出 N 天／永久停權／解封；操作要影響驗證及進行中 Session。天數上限、時區顯示、停權理由必填、對目前在線者的處置方式、既有封禁是否允許覆寫均是**設計提案**，需要正式確認才上線。

三筆 REQ 使用**同一份原始需求紀錄**，但驗收結果不同；不另建第四種來源，不冒充 CLIENT_NATIVE 證據。

## 不在本次使用者要求內，暫不擅自擴充的功能

- 玩家自行註冊、忘記密碼、Email 寄信／驗證、驗證碼、批次停權、IP／裝置封禁、角色刪改、GM 遊戲內指令、課金/權限管理、帳號刪除與恢復。
- 初版後台限經管理者明確配置的存取環境；**不代表已授權公開網際網路部署**。
- 以上可列後續產品候選，但**不建立正式 REQ 或 RR**。

## 補充需求（同一對話，2026-10-31）

> 目前先不管權限，指定的IP與URL就能管理

**依使用者的新限定更新 V1 存取方式**：本階段不做管理員帳號、登入、MFA、角色或細部 RBAC；改為**固定 WEB base URL／Host 加上 Server-side 來源 IP allowlist** 的單一全功能管理介面。此為 `REQ-0006` 同一需求的**第二筆 PLAYER_ADMIN_REQUEST discovery**，不是新 REQ，也不代表 IP+URL 具備與使用者認證等價的安全性。

- 來源 IP 是實際請求的**客戶端來源位址**，非 Server 自己的 IP；URL 是管理入口的配置位置，**不是**保密憑證。未指定具體 IP、網域、埠或路徑，不能自行填入真正可對外存取的值。
- 入口限私有網路/VPN/本機或安全邊界內；來源 IP 在共用 NAT/VPN 後可能代表多人，不能辨認個別操作者。
- 仍保留：伺服器端 IP/Host/path 驗證、預設拒絕、TLS（跨主機）、CSRF/Origin 防護、請求節流、操作確認及可靠稽核（稽核 actor 可記 `IP_ONLY_OPERATOR` + 來源 IP，**不冒稱特定管理員身分**）。
- 不改變 REQ-0007／0008 的新增帳號、N天／永久停權與解封功能驗收；它們改由 V1 受允許來源的管理操作執行，不要求管理員登入。
- 正式規劃見 [WEB Admin V1](../../admin-web/ADMIN-WEB-V1-PLAN.md)、[ADR-0004](../../decisions/ADR-0004-admin-web-security-boundary.md)。未授權開放公網部署或自動修改現有 Server Host。
