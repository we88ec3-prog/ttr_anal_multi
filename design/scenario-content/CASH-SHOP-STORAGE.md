# 商城保管箱保存與初始化

2026-11-18 接續商城開發。來源為 [商城餘額與保管箱欄位](../../governance/client-variants/20261118-cash-shop/BALANCE-AND-STORAGE.md)，固定 KR BIN SHA-256 `9741d1975327b9309d82b52f631165bc410757694d7c183a5eed970a53ebef91`、指定 v2 SHA-256 `6f92ba12d83cd75668353ca175122309ffa5b35a9fa2fee9fe85e2c0350d3b3c`。本頁規劃 Server 的保存與發布，購買、領取交易及完整實機購物仍待接續。

## 保存邊界

本頁保存 V25 階段與預置記錄驗證。接續的 [付款與領取](CASH-SHOP-CHECKOUT-AND-CLAIM.md) 已實作共同交易、實際購物車、領取與 V26 多格商城堆疊；本頁下方的「仍待實作」是前一階段歷史範圍，不代表最新程式仍只支援預置。

本機商城記錄以帳號及兩個 u32 記錄鍵識別。記錄包含 Product、u32 時間原值，以及數量、期間、選項三個 byte。記錄鍵與一般背包 metadata 分別保存，後續領取依這組鍵找同帳號的保管箱項目。

Server 元件 V25 在原有錢包上建立 `local_cash_shop_items`。V24 及更早已支援的元件沿既有遷移鏈升級，原本錢包、背包、裝備、銀行與任務資產保留。反覆啟動時沿用已存記錄。時間欄命名 `time_value`，其 u32 位元保留，期限含義與到期規則仍待核對。

讀取使用當前帳號的有效遊戲租約，在同一個 SQLite 讀取交易內取得 Garnet 與該帳號的商城記錄。跨帳號的記錄不加入此份快照。紀錄的發布順序按高／低鍵排序，排序屬本機 Server 決策。

## 正常世界初始化

啟用現行交易服務後，正常廣場／村莊的首次資產恢復會發布已保存的 `00DD` 餘額，接著發保管箱清單。沿用現有世界初始化的發送佇列，在該次載入含有 `0024` 時，把資產放在場景啟用之前。

| application | 本機發布方式 |
|---|---|
| `00E2` | 第一包先清除 Client 舊清單，再載入列；沒有記錄時仍發 `E2 00` |
| `00E3` | 後續包追加其餘列，維持同一次初始化的原記錄鍵與欄位 |

每列 19 bytes，沿用來源 consumer 的偏移。

| 列偏移 | 型別與值 |
|---|---|
| +0 | u32 記錄低鍵 |
| +4 | u32 記錄高鍵 |
| +8 | u32 Product |
| +0C | u32 時間原值 |
| +10 | u8 數量 |
| +11 | u8 期間原值 |
| +12 | u8 選項原值 |

每包最多 215 列，命令加完整列為 4,087 bytes，符合目前的 4,096-byte 封包預算。更多記錄分包發布。這個分包數屬 Server 發送政策，Client 接收器的原生行為以既有來源為準。

初始化通知另補原件核對：`50AC70/50ADA0` 更新清單後使用 `58AFA0` 發 `F429F` 給 class `F1`。`58B030..58B040` 查視窗登錄，miss 保持空目標；`58B06F..58B07E` 將目標與事件加入 `FXUI+1444` 佇列。`74EF94..74EFAA` 消費同一佇列時先測目標非空，才呼叫 vtable `+15C`。因此缺少登錄視窗不會在這條路徑直接解參考空目標；並非強制建立商城 UI，也不代表尚未實機驗證的開窗與顯示已通過。[指令](../../governance/client-variants/20261118-cash-shop/dispatch-instructions.txt)、[四個原件視窗收據](../../governance/client-variants/20261118-cash-shop/dispatch-verification.json)、[唯讀驗證器](../../governance/client-variants/20261118-cash-shop/verify_dispatch.py)。`F95C54 - F94810 = 1444h`，與原 consumer 的佇列偏移相同。這是限定來源核對，沒有擴成完整 UI lifecycle 驗收。

## 已覆蓋與後續驗收

合成正常案例從全新 SQLite 元件與已命名帳號開始，重建 V24 形狀後升級，核對初始空保管箱。兩筆保管箱記錄由隔離資料庫預置，Product 為 27461、27484。再次遷移及重開儲存層後，記錄鍵、時間原值、數量及錢包 120 保留。從正常世界入口讀取並發布 `00DD` 及 `00E2`，逐欄核對兩筆記錄及其 19-byte 間距。同次初始化完成後，既有恢復旗標維持一次發布。

這兩筆資料的來源是合成預置，購買提交與領取入包仍待實作。保管箱的物品顯示、分頁、時間文字與正常開窗須在指定 v2 批次核對，實機與換版目前保持暫停。

Release Host、離線檢查器建置皆為 0 warning／0 error，`Category=HappyPath` **564/564** 通過。新收據 `outputs/fresh-cash-storage-bootstrap.json`（本機，SHA-256 `6370a4606400e4c67e982783e45cd29fc75bc79457366aaf2f853a453b542ed6`）完成全新帳號到 Q144、Town 3／圖 199、八個一般狩獵場、自然前置 Q2849／Q2850→Q2852、同登入 RAID→Stage 465 與 RAID 1～3／經驗書的離線回歸。這份回歸核對既有旅程不受新初始化包影響，不把預置商城記錄視為已購買。
