# KR 裝備穿脫封包與欄位

證據來源為 KR 原件 `Tartaros.bin`，SHA-256 `9741d1975327b9309d82b52f631165bc410757694d7c183a5eed970a53ebef91`。本文位置皆為 VA。指令原始位元組可由 VA 減 `0x400C00` 對照。此輪確認發送端與裝備資料接收端，Server 合成驗證封包讀寫，實機穿脫未驗收。

## Client 發送

| 操作 | C2S payload | 指令依據 |
|---|---|---|
| 從背包穿上 | `0023:u16, role:u8, equipSlot:u8, bagKind:u8, bagSlot:u8`，共 6 bytes | 裝備格拖放 `5E0D90` 與背包操作 `601130` 分別在 `5E10C3`、`60144A` 呼叫 `4A3840`。`5E0DFB–5E0E0F` 取包種類並把格位索引加 1。背包路徑 `6011A8–6011E3` 檢查 bagKind 為 1、格位為 1–100 |
| 從裝備格卸下 | `0029:u16, role:u8, equipSlot:u8`，共 4 bytes | `5E111E–5E112C` 從裝備格物件 `+298h`、`+29Ch` 取角色與裝備格，再呼叫 `4A3890`。請求未帶目的背包格 |

裝備格拖放在 `5E0E17–5E0E61` 以 Item class 減 1 查 `520F40`，並檢查結果等於目標格。依 `520FE8` 的 43-byte 索引與 `520FA8` 的跳表，class → slot 為 `1→1, 2→2, 3→3, 4→5, 17→6, 18→7, 19→8, 27→4, 32→9, 36→10, 37→11, 40→12, 41→13, 42→14, 43→15`。這條路徑的其他 class 返回 0。馮德斯鍊金店石類 class 11 在此路徑沒有裝備格。Client 發送前還會檢查角色與等級。Server 應按已授權角色、實際 Product 與 Item 資料重新驗證。

## Client 接收

`4E1DBF` 將 player-state 分派表 `+384h` 綁到 `4E2400`（S2C `0070`）。後者呼叫 `509A80`。角色索引為 payload `+2`，接收端接受 1–15。`+3` 的 WORD 與 `+5` 的 byte 分別寫到角色裝備容器 `+100h`、`+102h`。這兩個欄位的原服語意待核對。

裝備列從 payload `+6` 開始，每列 15 bytes。接收端依長度套用指定格位，可接收一列或完整快照。

| 列內位移 | 格式 | 接收行為 |
|---|---|---|
| 0 | u8 | 裝備格 1–15 |
| 1、5 | 各 u32 LE | 存到該格 `+8h`、`+Ch` |
| 9 | u16 LE | 存到該格 `+0`。為 0 時將該格四個 DWORD 清零 |
| 11 | u32 LE | 存到該格 `+4h` |

同號命令需看方向。既有 S2C `0023` 是換場畫面，S2C `0029` 是背包初始化。Server 既有教學裝備 `0070` 仍用原先數值及完整 15 格，並沿用後續 `00F9`、`00FA`。穿脫完成通知和其他玩家的外觀更新順序仍待確認。

背包拖放路徑 `5E0EE3–5E0EF5` 用背包格的 `+10h`、`+14h` 查輔助資料，命中時檢查回傳記錄 `+24h`。另一條背包路徑 `5E06B0` 也經 `4DD400` 查詢。該樹先比較有號高 DWORD，再比較無號低 DWORD，因此兩欄合在一起有查詢鍵用途。 [背包格位寫入格式](../../governance/client-variants/20261109-mef-town-services/shop-asset-sync.md)

同一資料結構的封包入口亦已定位。S2C `007B` 由 `4E1EBF` 登記至 `4E3160`，要求 payload `+4` 的 DWORD 等於 1。成功經 `4E320B–4E3211` 呼叫 CustomItem 接收器 `4DCA20`，其列從 `+8` 起、每列 27 bytes。S2C `007D` 由 `4E1EDF` 登記至 `4E3240`，使用 payload `+2`、`+6` 的兩個 DWORD 查找並刪除該鍵。CustomItem 列內欄位、新物品鍵值配置，以及何時必須發布 CustomItem，仍待查證。

裝備格的 `+4h`、`+8h`、`+Ch` 在 `5E6140–5E6160` 交給同一個資格查核 `5E06B0`。其中 `+4h` 進 Product 查表，後兩欄進上述輔助資料的組合鍵查詢。因此此候選的 `0070` 用 `Item 2607` 填列內 `+9`、`Product 2614` 填 `+11`，背包既有 metadata 依序填 `+1` 與 `+5`。包頭兩個附加欄位沿用既有相容 Server 送零的策略。裝備拖放在 `5E10CC` 還會呼叫 `5E0C40`，該函式送出 `00BD` 和角色／格位，後續應答與 3D 外觀更新仍待驗證。

| 位元組範圍，左閉右開 | SHA-256 |
|---|---|
| `4A3840–4A38CC` | `aaf16ab895113ba0918d20865bf6ddf9bc0c53453aa465979ec167d40a0ab91e` |
| `520FA8–521013` | `ee6bbf8f65c8c12c2f021fd5a6393ae4587249e3b620185889b6bd702c9c02c7` |
| `509A80–509B90` | `7902268a5b2d05eb455565a9f076f7193e168503cab98cba5aedbb8139605cf3` |

## S00 開發需求

第一個穿脫落盤候選為 Product 2614／Item 2607。韓版 `ItemTable2.xml` 的 SHA-256 為 `7095f005d26a67694112ce4c89d2725478d2287181e639fb18956b3d0bf5e2e2`。Item 2607 為 class 1、`quan=1`、`USE_LIMIT char="1"`，未列最低或最高等級，`EQUIP_POS_LIST` 只有格 1。Server 現有冒險團角色表的 1 是索瑪。交易必須驗證有效租約、已命名冒險團、角色所有權與原背包格內的獨立實例。

SQLite V7 新增角色裝備格。穿上時同一交易移除背包實例並寫入裝備欄。若目標已有裝備，原裝備回到剛空出的背包格。卸下時選擇第一個可用背包格。GUID、Product 和兩個既有 metadata 欄位原值隨物品移動。交易提交後回傳變更的兩格，讀取接口可在重開資料庫後回讀。舊錢包、背包、倉庫與掉落記錄繼續由原表保存。

合成案例將兩件同款、不同 metadata 的裝備依序穿上，驗證交換、重開讀回及卸下。遊戲接線由 `TARTAROS_LOCAL_EQUIPMENT_MODE=LOCAL_PHINDOS_EQUIPMENT_CANDIDATE` 明確啟用，依賴已保存的廣場流程、主線和共用背包。舊模式名稱 `LOCAL_SOMA_EQUIPMENT_CANDIDATE` 保留為相同模式的別名。一般廣場及村莊處理穿脫請求，提交後依序發送 `002C` 與 `0070` 單格更新。

Server 已將馮德斯 30 筆可穿戴商品的 Product、Item、裝備格、指定角色及最低等級整理成[規則表](phindos-equipment.rules.json)。資料來自相同 SHA 固定的 ShopInfo、Product 及 ItemTable2，以 `USE_LIMIT`、`EQUIP_POS_LIST` 與原程式的 class → slot 表交叉核對。沒有指定角色或最低等級時欄位填 0。四筆有最低等級，Product 9496 需角色 9 達 8 級，Product 29022、29023、29024 需 10 級。Server 目前正常流程等級以角色 2 為 1、角色 4 為 2、其他角色為 5 的既有值檢查。正式角色等級進度仍待接入，測試頁顯示值不作資格依據。

## 三村穿戴規則

[三村規則表](three-village-equipment.rules.json)的 SHA-256 為 `e7716119176450d557db9e405ea513a14217d76e6aed17c5556452dd516ee2ea`。以同版 ShopInfo → Product → ItemTable2 新增 54 筆。爾勒梅斯 Shop 6 的 27 件一律要求 Lv.10，羅特魯亞 Shop 10 的 27 件一律要求 Lv.15。每村有九角色各三件，class 1、2、43 分別對應格 1、2、15。每件以該列的角色限制與唯一的 `EQUIP_POS_LIST` 核對。

Server 穿戴時使用資料庫角色等級，尚無成長紀錄的角色採既有初始值。穿脫、重登快照及獨立物品 ID 沿用既有流程。表格為 Server 自訂規格，分類為 `NOT_NATIVE_MEF`。新品購買仍需要已核對的入包 metadata，裝備能力值與 3D 外觀另待驗收。

正常重登由同一資料庫快照讀取背包與所有已擁有角色的裝備，進廣場時各發一份 15 格快照，換角或換圖重建時刷新目前角色。啟用後正常世界以已保存的裝備欄提供全部格位，空格發送清除列。教學期間仍走原有裝備初始化。測試跳轉不啟用此路徑。
