# 地面掉落與 Space 撿取

狀態為 S00 離線分析與 Server 封包合成測試。正式掉落表、撿取入包和實機驗收待完成。此項開發沿用目前的戰鬥流程，地圖與怪物 MEF 分析暫停。

## KR Client 讀取的地面道具

來源為 KR 原件 `Tartaros.bin`，SHA-256 `9741d1975327b9309d82b52f631165bc410757694d7c183a5eed970a53ebef91`。程式位置使用 VA，對照檔案位移時減去 `0x400C00`。

S2C `0021` 的入口在 `0x4ADECD` 登記至 `0x4B2CD0`。函式按 `(payloadBytes - 2) / 31` 讀取資料列（`0x4B2D44–0x4B2D77`），從 opcode 後第一個位元組開始，以 31 bytes 為步長建立 `CDropItem`（`0x4B2EB9–0x4B2F52`、`0x4B301B`）。欄位均為 little-endian。

| 列內位移 | 型別 | 已確認行為 |
|---|---|---|
| 0 | u16 | 地面物件 ID。Space 搜尋接受低位元組為 3 的物件 |
| 2 | u16 | 外觀選擇值。建立時與 `0x03000000` 做 OR，實際資源對照待核對 |
| 4 | 2 bytes | 此處理函式未讀取，合成封包填零 |
| 6、10 | f32、f32 | 起始 X、Y |
| 14、18 | f32、f32 | 落點 X、Y |
| 22 | u32 | 非零時設物件 `+0xF4`，用途待核對 |
| 26 | u32 | Product ID，寫入物件 `+0x11C`。後續在 `0x4D0A10` 使用 Product 表 |
| 30 | u8 | 數量，後續由 `0x45F1B0` 讀取 |

S2C `001A` 可按同一 ID 移除地面物件。入口 `0x4B28D0` 在 `0x4B2AB5–0x4B2AC7` 呼叫物件管理器 `0x4DFBC0`。Server 可沿用現有六位元組移除封包。

## Space 的請求與後續接線

- [T10 輸入契約](../../kr-temp-roy/T10/20261103-T10-T11-KR-INPUT-CONTRACT/input-contract.md) 將邏輯輸入 23 對應為 Space。`0x49C74F–0x49C77D` 處理按下階段，`0x49CE10` 搜尋鄰近候選。`0x49CEF0–0x49CF62` 檢查物件類別、條件式檢查 Product 並比較位置。
- `0x44481F–0x44482F` 寫入 C2S `0007`，`0x4448B5–0x4448BE` 對 Space 將第三個位元組設上 `0x80`，`0x4448DC–0x4448E4` 送出三位元組 payload。`0x548888–0x5488A6` 與 `0x5489B9–0x5489EC` 提供另一條相同長度的路徑。封包沒有目標物件 ID，且第三個位元組可同時含其他輸入旗標。
- Server 預計按目前場景、權威位置與掉落歸屬選取可撿物件，成功入包才發布更新及 `001A`。背包滿或持久化失敗時保留地面物件。正式半徑、外觀選擇值、背包 `002C` 的撿取更新方式，仍須查證。
- 可由 Server 自訂內容表定義掉落來源、Product 和數量。後續新增內容表時須採獨立 schema 與副檔名，標示 `NOT_NATIVE_MEF`。這輪新增封包編解碼，尚未接入現行戰鬥、掉落表或執行中的 Server。
