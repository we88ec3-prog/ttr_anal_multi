# 消耗道具機關：世界接線與正常旅程

狀態：WORLD／JSON_AUTHORING_READY；圖形成本欄位與Client實機仍待完成。
接續[交易層](SCENARIO-CONSUME-GATE-TRANSACTION.md)，將消耗接到既有

## 內容契約

`interaction.consumption` 為可省略的 `{product,quantity}`：非零uint Product、
quantity1～255。未配置者保持既有同步機關；配置者須由已提交的資產收據
才能設立訊號旗標。已知獨立裝備Product不作成本；交易層也不取帶獨立裝備
身分的格或銀行。其他成本須具有實際可取得、含metadata的共用背包堆疊，
本批不宣稱已完成所有Product的供應／分類政策檢查。

新欄位為可選且null不寫出，原不含成本的範本、內容SHA與Profile算法維持。
JSON schema的公開版、文件版與來源伴隨版同步；來源伴隨版先前落後既有
訊號／條件欄位，本批一起對齊，不把舊版不足當成已驗完整。
可用[範例](case693-consume-checkpoint.scenario.json)經既有JSON保存／匯出流程
編排成本；目前簡易表單會保留原JSON中的成本，但尚無專用成本輸入欄位。

## 准入、提交及發布

每個不可變關卡instance取得Server run GUID與實際catalog SHA；規劃fork
保留同一身分，旗標與時計仍各自複製。操作收據以run＋node＋interaction
區分同場機關，並綁定版本、角色、Product及quantity。

既有 `001C category1` 僅提供互動鍵。正常狩獵場或主線Encounter／Portal
中的world adapter核對目前instance、已載入、角色所有權、玩家存活、
機關前置旗標／清場、區域及既有路徑政策，再從凍結內容產生可信成本。
一般狩獵使用原靜態路徑核對；主線沿用原動態屏障政策。

LocalTownTradeSession呼叫交易服務。成功後依序發布既有002C背包／錢包
差額、回復道具快捷列的實際總量，再以同一instance／node／版本／角色／
成本相符的收據設旗標，發布出口0048與機關狀態。未提交沒有成功收據，也
不能由同步InteractCheckpoint直接設立成本機關旗標。
提交後再次核對目前instance與前置，不憑任意回報跳過。

這裡只保證本批正常成功路線；操作中斷、失敗／重送、並發或跨登入run恢復
依既有排程另驗。持久交易收據不等於整場關卡保存／恢復已開發完成。
