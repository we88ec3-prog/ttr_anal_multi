## Client 入口

背包使用函式 `5FFF60` 的 class 29 分支讀取商品 `+5Ch` 的包裹列，確認背包空格後進入 `F436B` 提示。既存反編譯與原指令對照如下。

| 階段 | 入口與欄位 |
|---|---|
| 確認 | `5FF420` 的 `F436B` 分支查正向結果 `06A7`，於 `5FF79E` 呼叫 `601030`。 |
| 選格 | `601030` 檢查背包 1、格位 1～100、該格 Product 和數量非零。於 `6010F2` 傳背包、格位、讀自格列 `+0Ch` 的 Product，以及尾段指標 0。 |
| 發送 | `4A39F0` 建立 8-byte 應用資料。偏移 0 是 C2S `0021:u16`，+2 是背包種類，+3 是 1 起算格位，+4 是 Product DWORD。尾段指標為 0 時長度維持 8。 |

## Server 交易

正常廣場或村莊可操作背包時，以目前有效連線、精確請求長度與 Product 23230 進入開包。在資料庫同一交易核對格位持有的精煉包、扣除一包、入包固定內容。背包有足夠格位與堆疊容量才提交。現行背包每個 Product 支援一疊。超過 255 時保留精煉包，可先使用或存入倉庫部分鍊石後重試。提交後以一個 `002C` 回覆覆寫受影響格位，錢包在開包時維持原值。原有格位若由內容物佔用，直接發布該格提交後的內容。

LeeLoo 袋走既有一般商店的 C2S `0020` 出售流程。只有在正常開店且位於服務範圍內，才交易背包內實際持有的格位。商店按原表以一個 10,000 LeeLoo 計算，扣掉實際出售數量並送既有錢包、背包及成交通知。這項商品只補上售價，商店貨單沒有新增販售。

## 離線驗證
