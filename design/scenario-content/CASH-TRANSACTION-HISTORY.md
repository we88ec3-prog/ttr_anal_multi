# 商城成交與領取帳本

2026-11-19 接續 CASH-MANAGEMENT-COMPLETION.md 的購買／領取歷史缺口。這是 Server 自有資料模型，不是官方資料庫或新 Client 協定。

## 原子寫入與版本

獨立元件 LOCAL_CASH_HISTORY_V1 隨既有交易 migration 初始化，不重編既有 V29。新增成交批次、商品來源、領取事件與領取格位表。正常購買的批次保存帳號、當時實際載入的商品目錄 SHA、扣款前後餘額、總額與 UTC 時間；每個商品保存原保管箱 key、Product、數量、期間、option、成交單價、PriceIndex 與 Item。寫入與原扣款／保管箱建立共用同一 SQLite 交易。

領取事件與背包格位變更、保管箱刪除共用交易；保存當時領取目錄 SHA、UTC 時間、受影響 slot、實際增加數量、完成後數量及獨立裝備識別碼。商品來源與成交事實不因領取刪除。這些事實是後續對帳／退款設計的基礎，本批不自動退款、不改 Client、不改封包。

## 舊資料界線

初始化只投影現存待領商品為 LEGACY_STORAGE，保存觀測時間及原 key，不填未知成本、目錄或購買時間。領取時也涵蓋初始化後由舊版 Host 建立的待領資料。已在舊版領取且沒有紀錄的商品無法回推，保留缺口。若混跑舊 Host，其新購買與領取不會寫入完整帳本；兩個服務須一起升版。

## 後台

獨立唯讀 `/admin/cash/history` 依登入帳號、Product、狀態查詢並分頁；顯示成交批次、價格／餘額、來源、待領／已領與目錄版本。缺少領取事件且保管箱也不存在時標示「待對帳」，不能當成已領取。商品名稱僅來自目前管理標籤，歷史身份由 Product／Item／key 與目錄 SHA 決定。

## 驗證範圍

授權 HappyPath 應覆蓋同批多商品成交、分次領取、拆堆與裝備身份、重開後歷史保留，以及既有待領商品補入與正常領取。獨立 Web HTTP 查詢檢查篩選及分頁。拒絕、重送、競爭、故障、安全與壓測仍依排程待測；工程與 HTTP 證據不代表指定 v2 實機驗收。驗證完成後追加收據，不以本規劃宣告通過。

## 本批結果

Release Host、檢查器與 Web 建置通過。兩項新增 HappyPath 通過，全套 594／594 通過；合併堆疊的增加量／最終量與獨立裝備識別已檢查。既有完整購買／領取回歸繼續涵蓋拆堆，未增加故障或拒絕測試。初次沙箱 testhost 連線逾時、尚未執行案例即中止；確認終止後正常權限重跑通過，保留原收據。Web 的初次 HTML 引號編譯錯誤也已修正，後續兩種輸出目錄建置均通過。

新增 `--cash-history-fixture <新DB絕對路徑> <商品目錄> <SHA>` 離線工具，拒絕覆寫既有資料庫；用正常 API 產生 54 筆／6 批付款、2 筆領取，再加 1 筆明示舊版待領 fixture。HTTP 檢查 55 筆的 50／5 分頁、2625 已領 2／待領 52、5342 舊版待領 1、金額與格位身份及搜尋值保持。此處的一筆舊來源是測試 fixture，非原生或歷史帳號證據。

原測試 DB 的獨立副本先完成 Host 隔離預檢。其後核對舊 Host／Admin 的 PID、路徑及五個 loopback listener，關閉指定服務並保留 SQLite 副本，再一次換成新 Host 與獨立部署的 Admin。原本五個埠與三個商城管理頁均已確認，資料庫的帳本／販售元件版本也已唯讀確認。首次進村私密一人隊伍設定保留；沒有重設進度或操作遊戲。新服務的實際購買／領取仍待使用者方便時驗收。

完整工程／HTTP／部署收據雜湊與待測界線見 [驗證索引](cash-transaction-history-validation.json)。本批部署也啟用前批商品販售管理；CASH-SALE-ADMINISTRATION.md 的「僅發布、未換版」保留為該批歷史狀態。
