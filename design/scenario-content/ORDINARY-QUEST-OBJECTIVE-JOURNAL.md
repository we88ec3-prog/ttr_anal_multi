# 普通任務目標計數與重登回填

現行範圍為前兩村的 87 項已接入普通任務。接取後登錄目標，擊倒或拾取後更新已保存的計數。重登經展示頁進廣場時，在場景啟用前回填 Accepted 與 Ready。已領取報酬的任務沿用 `006F` 完成旗標。

## Client 的目標文字與計數

原版 QuestInfo 解碼 SHA-256 為 `5d251415fdfdc453adefbff03114ded5a8ea41b696ce0aab86a23070e0fdca60`。`504740` 讀取 `Contents/Content/@id`，在 `5052D1` 加 1000，再由 `505870` 以此鍵存入該任務的文字樹。`632280` 遍歷目標紀錄時，以記錄 `+14h` 的任務鍵和畫面選取的任務配對。子型 11 把記錄 `+2` 的 WORD 作為該任務文字樹的查詢鍵。由此可用原表 Content ID 加 1000，讓 Client 取原有文字。87 項的 89 個目標鍵各自唯一，Q10 和 Q67 各有兩個目標，依原表順序和 Server 判定對齊。 [T16 原件指令](../../kr-temp-roy/20261028-202944-chatgpt-web-roy-T16-90-KR-QuestInfo-QuestTalk-map-writers.md)

## Server 同步順序

- 接取提交後先送 `0040`，再用 `0042` 登錄初始計數。擊倒與拾取的 `0041` 只發送已提交的值。集滿時先更新計數，再發 `0045`。Q2842 的對話和 Q2843 的選關沿用目前 Server 規則，目標以 0／1 記錄。
- 重登以有效租約讀取同一帳號的 Accepted、Ready 與收集品庫存。按狀態順序先送 Ready，再按任務 ID，最多 20 項。Ready 以目標滿值回填。既有超出 20 格的存檔仍可由 Server 交付。接取容量見 [普通任務清單容量](ORDINARY-QUEST-JOURNAL-CAPACITY.md)。
- 指定 v2 待確認任務手冊實際呈現、NPC 待交標記及一般副本內即時計數。 [AQ-30](../testing/S00-CONTENT-BATCH-TESTS.md)
