# 逐波清除訊號

Server 自訂關卡可用 `WaveCleared` 旗標區分「這波怪物已倒下」和「整場已完成」。省略 `waveId` 或指定 null 代表入場時的第一批怪物。指定名稱則引用同一節點的順序或定時增援 ID，名稱區分大小寫。

```json
[
  { "flag": "initial-defeated", "event": "WaveCleared" },
  { "flag": "second-defeated", "event": "WaveCleared", "waveId": "checkpoint-reinforcement" }
]
```

- 指定波次生成後，當其所有怪物的 Server HP 歸零時鎖存旗標。尚未生成的波次不會觸發。不同波次的存活怪物不影響這個判定。
- 同一次更新先處理戰鬥傷害，再記錄已清除的波次，然後檢查後續增援。旗標也可解鎖互動點。整場出口與結算仍等候全部波次、剩餘投射物和既有清場流程。
- 載入時依序推導可生成的增援與可取得的旗標。若波次必須靠它自己、尚不可達的後續波次或整場清場才能生成，資料會被拒絕。分支匯合只使用每條路徑都必然取得的先前旗標。
- 旗標只存在於當次關卡實例，離開節點後可供同一實例的後續節點使用。離開副本時沿用既有進度保存邊界。

圖 193 的獨立場景使用三波各一隻怪。第一波倒下才開啟進場處的互動點，按 Z 生成第二波。第二波倒下後，第三波依順序延遲生成。清完第三波才開出口。座標沿用既有互動測試場。 [JSON Schema](local-scenario-definition.schema.json)

此規則由 Server 執行，內容使用 `NOT_NATIVE_MEF` 格式。
