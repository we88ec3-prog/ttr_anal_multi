## 點數商城接線前需閉合的流程

1. 原 UI 入口、允許場景、開窗時向 Server 發出的請求，以及初始化所需的回覆。
2. 商品的原表鍵、數量、期間、售價和付款幣別，及 Server 端可採用的版本化目錄。
3. 購物車確認的精確 C2S 格式、實際使用的連線，以及 S2C 結果的接收器。
4. 付款後的道具位置，商城保管箱、領取與一般背包之間的原請求及更新格式。
5. 付款和道具產生的共同提交邊界、裝備實例及 metadata、期間資料與登入恢復。
6. 由正常購買取得一件可穿戴商品及可堆疊商品，接現有換裝、銷毀和銀行流程。逐次核對幣別、原格清除、新格與裝備身分。

下次工程變更由已閉合的最小收發流程開始，使用既有租約、持久化與背包發布元件。此頁是現行交付查核及接續計畫，正式 REQ／RR／GAP 的狀態仍以既有台帳為準。
