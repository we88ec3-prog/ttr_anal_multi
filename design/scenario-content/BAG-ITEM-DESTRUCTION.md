# 背包整格破壞

## 原版 Client 請求與提示

背包選定格位後，`5FCA30` 將 1 起算格位交給 `5FCC60`。它從背包資料和 Product 查道具，普通確認使用訊息 `kItemDestroy_Request`（索引 `E9h`）。`5FB8C0` 收到確認時檢查強化或附加能力標誌，需要第二次確認時使用 `kItemDestroy_DeleteItemRequsetMsg`（索引 `EEh`），待 `F4425` 正向回覆後才走同一送出函式。強化等級讀 CustomItem `+30h`。這條路徑獨立於工匠分解和商店出售。

| 方向 | 應用層資料 | Client 行為 |
|---|---|---|
| C2S `007F` | `[7F 00 01 slot]`，4 bytes，背包種類 1，格位 1～100 | `5FD080` 驗目前格子有物品，走既有發送槽。請求沒有數量、Product 或地面座標。 |
| S2C `0062` | 在已核對的一般狀態，`+2` 為有號狀態；0 選成功通知 | `4BCB40` 把 `4BD2F0` 安裝在 `+61BCh`。`4C4670` 以 `5EACh + opcode × 8` 索引，對應 `0062`。成功分支取訊息 33h，即 `kDeleteItemMessage`。其他狀態分支與場景可能使用其他提示。 |

`0062` 的入口在 `4BD31A` 讀狀態，成功分支使用本機訊息鍵，背包移除由獨立格位更新處理。指定 v2 的成功提示是否完整代入品名與數量仍需實機核對。

## Server 交易

正常已載入且可操作背包時，依有效租約和當前格位取得要移除的道具。以整個堆疊為單位移除，維持錢包各幣別。任務專用收集品仍經普通任務交付或放棄的共用流程處理，保留其數量和任務進度一致。裝備須在背包。若該件有 Server 保存的強化列，在同一筆交易清除該列。

提交後先發 `002C` 將格位數量歸零。若銷毀的是已強化裝備，追加同一件的 `007D`。若是已綁定的回復道具，以 `0061` 發數量 0，保留綁定供日後補貨復用。最後發 `0062/00`。這是 Server 發送順序，整格移除與通知需在指定 v2 驗收。 [背包格位格式](../../governance/client-variants/20261109-mef-town-services/shop-asset-sync.md) · [強化列清理](EARLY-EQUIPMENT-DISMANTLE.md)
