# 商城管理接續範圍

使用者最新順序：先完成商城管理，再確認 MEF 分析狀況，閉合副本 MEF 分析並開發副本。這取代較早先做 MEF 的排程，不解除 Client／原件／執行限制。實機提問與「之後再測試」不停止獨立開發。

| 工作 | 當前工程證據／待辦 |
|---|---|
| 帳號查詢、Garnet 加扣、原因與操作記錄 | 已有 SQLite Web／交易正流程與合法 HTTP 證據；00A8 同次登入重整已獲使用者「可以正常更新」 |
| 待領商品檢視 | 目前列帳號／Product／數量；已有正常購買→領取及實機保存觀察。新增持久帳本見 CASH-TRANSACTION-HISTORY.md，工程驗證與換版紀錄另列 |
| 商品查詢與販售控制 | 本輪補名稱、來源版本、Client 列表有無、固定價格、停賣／恢復及稽核；已支援商品限定，實機及拒絕流程仍待驗 |
| 價格、顯示列表及配套發布 | 尚未完成。後台編輯與 Client 原列表一致性需另有草稿／差異／匯出／部署方案，不能只改 Server 收費；尚無已證動態全列表封包，也未獲新玩法資源修改授權 |
| 購買／領取歷史、管理追蹤與對帳 | 已有成交／領取帳本。新增 CASH-RECONCILIATION.md 的資金起點、管理加扣／成交／銀行支出來源及前後鏈、商品差異明細與分頁；這批準備中，併管理處置換版。啟用前未知收支不回推，差異與故障案例仍依排程待測，不能宣告全歷史已還原 |
| 管理補發／撤回／退款等後續操作 | 尚未完整規劃／實作；先依交易帳本與既有資產權威界線設計，再逐項驗證，不任意覆寫背包或偽裝正常購買 |
| 所有特殊商品用途 | 仍依 CASH-SHOP-FEATURE-COVERAGE.md 分項開發／待驗，不能由管理頁存在推成商品效果完成 |

商城管理整體仍未完成。各批完成後先建置與授權 HappyPath、分層記錄工程／HTTP／指定 v2，再推分析規劃及私有 Server 的 main。首次進村私密一人隊伍實機測試依使用者要求延後，與商城管理及後續 MEF 完成狀態分開。
