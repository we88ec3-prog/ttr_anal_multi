# 商城管理接續範圍

## 最新收尾與停止範圍（2026-11-19）

使用者要求：「商城管理系統完成後先暫停開發並推上git」。商城管理完成、建置與授權正流程驗證通過、兩庫 main 推送後即停止開發，不接續 MEF／副本或其他商品效果。先前持續開發排程由此要求取代；退款／真實金流仍不列入範圍。

價格／列表配套目前仍只有草稿及提案匯出，不能宣稱完整發布功能完成。本次已提出具體授權選擇：管理端產生新的 Table.stp 工作副本及相符 Server 目錄，保留原件／舊版，不自動替換現行遊戲資源；或由使用者明確選擇延後配套生成。授權／範圍選擇尚待回覆。其他既有管理檢查與操作交接可先完成；待驗實機項目保留，不因收尾而改成通過。

私有 Server 補 `docs/CASH-MANAGEMENT-OPERATOR-GUIDE.md`，記錄目前啟動方式、各管理入口、寶石／補發／領取／販售控制及草稿操作。這份交接不代表已新增配套生成／發布功能。

本批 Host／檢查器／Web Release 建置皆為零警告與錯誤，635／635 HappyPath 通過；六個既有商城管理入口 HTTP 200。只有交接／範圍文件變更，沒有改遊戲程式、Client 資源、線上價格或玩家草稿。收據見 [收尾檢查](cash-management-closeout-checks.json)。

2026-11-19 使用者最新定位：「不用處理退款，遊戲本身沒有要有現金流」、「只是朋友交流分享」。後續以朋友私人遊玩的帳號、虛擬 Garnet 發放、商品列表／價格、基本紀錄與副本 MEF 為範圍；退款／金流不再列開發與人工驗收目標。既有程式、資料與歷史證據保留，不把已做功能當成新的必要前置。沒有真實支付整合。

使用者最新順序：先完成商城管理，再確認 MEF 分析狀況，閉合副本 MEF 分析並開發副本。這取代較早先做 MEF 的排程，不解除 Client／原件／執行限制。實機提問與「之後再測試」不停止獨立開發。
