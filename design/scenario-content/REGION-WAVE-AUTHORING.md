# 用資料配置順序波次與區域增援

這是 Server 自訂關卡內容，NOT_NATIVE_MEF。範例未套用正式關卡；座標、
怪物數量與延遲均為作者示範值，不是官方影片／MEF還原結果，也未人測。

|欄位|何時生效|如何填寫|
|---|---|---|
|encounters|節點入場的第一波|model、x、y；可用aiProfile覆寫節點預設|
|reinforcements|依陣列順序的後續波次|每波id必須不同，不另建地圖或重建玩家|
|delaySeconds|前一波清完後開始計時|0到3600秒；不是從進圖開始|
|activationRegion|延遲到期後檢查玩家當前位置|x/y圓心與radius；圓周算區域內，可省略|
|GroupCleared|最後一波真正清完|才解鎖出口，不在每波清完時提交任務勝利|
|InteractZ|已解鎖出口範圍內按Z|NextNode換圖或Result進結算|

區域、延遲、前波清完三條件必須同時成立。先進區域又離開，不會記成
曾觸發；到期時人在外面，需重新走入。沒有掃掠路徑偵測。定時並行增援另見
[S00定時增援契約](../../governance/s00-iterations/S00-20261111-TIMED-REINFORCEMENTS.md)；
本範例只示範順序增援。任意條件分支、召喚或腳本執行仍列待開發。

波次沿用同一戰鬥物件，保留HP、MP、SP、冷卻與輸入；新增怪物使用新ID，
不重用死亡怪ID。單節點初始加後續怪合計最多255隻，額外波次最多31波。
新增怪使用自己的AI起始延遲，既有怪物不因換波重置。

旁邊region-wave-example.scenario.json提供單節點、第一波加兩次增援：
先清第一波；延遲2秒且人在指定區域時生第二波；清完再等1秒生第三波；
最後清完才解鎖出口，走進出口按Z結算。第二波示範個別aiProfile欄位。

使用前依各圖BND核對玩家出生、全部生怪位置、區域中心與出口，並逐圖
確認路徑、出口通道底端、大型傳送陣及怪物離玩家的安全距離。
範例只供內容編寫／載入驗證，不應直接替換正式主線內容。

JSON schema只檢查結構；typed loader另查SHA、有限圖序、ID及引用等規則，
adapter還會查BND與AI profile。修改任何內容後都要重新計算SHA並更新
明確的載入設定。正式部署與人測另行安排；原生MEF能力狀態不因此改變。
