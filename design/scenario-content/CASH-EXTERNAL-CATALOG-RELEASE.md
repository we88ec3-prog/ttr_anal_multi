# 獨立商城檔與管理端配套匯出

2026-11-19 使用者明確要求先確認實際讀取路徑，完成主程式讀取獨立商城檔的修改，保留原件與舊版；商城管理完成後推上 Git 並暫停開發。此授權涵蓋本方案的商城資源工作副本及新命名 EXE，不授權代理啟動／附加／操作遊戲。退款與真實金流不在開發範圍。

## Client 讀取與更新方式

指定 v2 原有商城解析器 `511E40` 在 `511E90` 將 `C0E098` 指向的完整路徑放入 ECX，再於 `511EA3` 呼叫 `72F110`。ECX 是檔名，不能因舊偽碼省略暫存器參數而把它當作無檔名呼叫。後續使用原有 XML／檔案讀取程式；來源與有限指令證據見 [載入鏈核對](../../governance/client-variants/20261119-cash-external-files/README.md)。

新工作副本只把完整 NUL 結尾字串 `Table/CashProduct.xml` 改為等長 `TC_Mall/CashTable.xml`，不改全域封裝掛載或其他表的路徑，不增加 Server 傳檔 opcode。商城資料仍用原有 CASH_PRODUCT_LIST／CASH_PRODUCT／PRICE_LIST 格式，非新增原生格式。新增 EXE 為 `Tartaros.ip-zh-tw-only-v2-mall-v1.exe`，舊 v2 與所有既有 STP 保留。最初獨立 XML 是現用 CashProduct 的逐 byte 副本，沒有自行更改商品或價格。

商城表由 singleton 建構載入；本批使用完整退出後再從遊戲目錄啟動新 EXE 的更新流程。沒有實作或宣稱熱重載、自動下載；寶石重整仍僅更新 Garnet。這次只需準備一次新 EXE，之後改商城列表／價格只更新獨立 XML 及匹配 Server 資料，不重產 Table.stp。新增主程式與解析路徑的靜態核對不等於指定 Client 實機通過。

## 固定來源與管理草稿

管理端以原版／現用兩份完整、唯讀、雜湊固定的 CashProduct XML 作模板，現用列優先，現用未列才使用原版模板。這些原始 member 僅保留本機，不推 Git。沿用既有 2,225 個模板的 Product／數量／期間／選項及來源身份，不憑空增加商品或改變用途。

每份草稿以固定來源基準記錄其完整目標設定。重複調整始終以該草稿對同一基準的差異產生全份配套，避免把不同部署的差異逐次疊加。管理端現用目錄／標籤與草稿基準分開設定；上線新價格後仍可編輯固定來源草稿。基準 SHA 改變的舊草稿維持只讀。

## 配套產生契約

管理者先核對草稿 ID、版本、價格與列表差異，再由管理頁下載此固定版本 ZIP；CSRF 檢查及明確審閱欄位沿用管理表單流程。相同來源／版本的包內容可重現，下載提供 SHA。ZIP 內容包含：

- `TC_Mall/CashTable.xml`：完整目標商城列表與標價。
- Server V3 `.cash-shop.json`：所有既有 offer 及新價格，保存來源／草稿／Client XML SHA 與管理定價身份。
- 匹配的管理端 labels：名稱、Client 是否列出、目錄 SHA。
- manifest 與操作說明：每個產物雜湊、固定草稿身份、相依版本及手動套用方式。

`listedProducts` 決定新購買是否在此版供應；offer 的 `Available` 繼續表示已實作的功能支援，不把未列商品誤標成未實作。新購買同時檢查功能支援、目錄列入與既有停賣規則。保留全部 offer 供已付款商品領取及正常管理補發，不因新列表移除既有待領權利。草稿不能開放尚未實作的商品效果，也不以修改價格增加該商品支援。

列入 XML 的已知模板使用明示管理販售政策：NOW_SELLING=1、SELLING_STATE=0、SELL_START_DAY=2000-01-01T00:00:00、SELL_END_DAY=2037-12-31T23:59:59，防止保留舊歷史日期使管理者選擇的商品被舊狀態篩掉。這是私人 Server 的管理設定，不是原服當期供應證據；其他分類、商品文字及選項保持模板值。

## 發布與回復

下載是產生配套，不會自動變更玩家資料、目前 Client 檔或正在運行的 Server。管理者保留舊配套，完整退出 Client，再以同一包 XML／Server 目錄／標籤及各自 SHA 設定作成組發布。原版與舊版資料保持唯讀；回復時整組切回舊版。管理端固定草稿基準不隨新 runtime 定價替換。

此流程不需要每次重新產生 EXE 或 Table.stp。增加新的道具模型、用途或其他不在既有模板的資源，仍是獨立開發項，不能靠商城列表宣稱完成。

## 完成與待驗分層

工程完成須有新 EXE 的最小差異／來源保留核對、模板與發布內容的逐項對照、管理端合法表單下載、固定版本可重現匯出、Server 正常購買／領取及既有 HappyPath 回歸。指定新 Client 的啟動、商品畫面、實際購買、領取及穿戴仍保留人工驗收；代理不操作遊戲。拒絕、重送、併發、安全／故障及壓測依既有排程待測。

工程驗證、兩庫 main 推送及交接完成後，依使用者要求暫停開發，不自動接續 MEF／副本或其他商品效果。

## 本批工程驗證結果

Host／檢查器／Web Release 皆零警告及錯誤，636／636 HappyPath 通過。實際原／現用模板經合法管理表單，產生改價 2625 為 300、移除 2627、加入原版模板 184 的隔離範例；相同版本 ZIP 逐 byte 相同，XML 列表與 Server listedProducts 一致，其餘非指定欄位與功能支援旗標保持。

實際匯出的 catalog 經 SQLite 正流程：先在舊版購買 2627 扣 250 未領，再在新版買 2625 扣 300，仍可領取舊 2627；餘額 1,000、待領一筆、交易兩筆且已知成本 550。新 catalog／labels 啟動隔離管理端，現價 300 與草稿固定基準 250 正確分開。新 EXE 身分及實際匯出配套經隔離 Host 正常啟動；只驗證檔案身分與設定，沒有執行 Client。

本機管理端已更新為 PID 34988，六個入口 HTTP 200，部署 DLL 與本次測試 build 相同。保留遊戲 Host PID 32188；備份為 `accounts-before-external-mall-20261119.db`。商城及副本草稿相關資料列指紋相同，範例定價與列表未發布到玩家環境。首次新 XML 是現用 member 的逐 byte 副本。
