## 1. 分段與驗收層

延續 Iteration 11：`SLICE-LOBBY`（登入、選服、角色清單、角色 UI）優先；`SLICE-CREATE`（建立角色）必須找到建立角色的獨立原生依據；`SLICE-ENTER-WORLD`（選角後進世界）另行驗收。以下 A/B/C 是**規劃驗收層級**，不建立新正式狀態機、不改 REQ/RR/GAP/SPEC。

| 層級 | 交付 | 不能宣稱 |
| --- | --- | --- |
| A `SOURCE_MAPPED` | 同版本 Client producer/consumer、條件、資料形狀與證據定位 | 真的接到原版 Server 回覆／畫面出現 |
| B `CONTRACT_TESTABLE` | 可依有界方向別 SPEC 製作測試，所有必要未知仍清楚封鎖 | 與原版 Client/Server 已相容 |
| C `CLIENT_RUNTIME_CONFIRMED` | 經另外明確授權的隔離實測，含環境、版本、收發與畫面證據 | 全版本所有情境都已還原 |

本輪核對基準：5 REQ 皆 `CANDIDATE`；6 TEST 均 `OFFLINE_SYNTHETIC`，7 SPEC `DRAFT/PARTIAL`、7 GAP `OPEN`；RR-0002 `BLOCKED`，RR-0005 `ACCEPTED` 僅限有界研究，其餘 RR `IN_REVIEW`。這些只記錄當時快照，不代替最新正式索引。

## 2. L00–L08 Server 檢查點（分析順序，不是證實的網路時間線）

| 檢查點 | Client 已有的有界觀察 | Server 需要形成的契約／未知 | 原主責與權威 |
| --- | --- | --- | --- |
| **L00 基礎連線** | T02 局部 WSASend、IOCP、slot/key、Connect 呼叫 | 確認首個實際 C2S/S2C、mode、Session、close/retry；local queue 不能推為 wire | T02，RR-0001/0004/0005，REQ-0002/0005 |
| **L01 認證請求** | 本地 mode 0x52 → E8/112 bytes，0x54/其他 → 000F/214 bytes，文字布局不同 | 實際執行時模式、E8 opaque bytes、必要 Server 欄位和 codepage；不可硬推 CP949/UTF8 | T03/T02，RR-0003，REQ-0001 |
| **L02 登入回覆** | 活躍 LOGIN scene 下 0x13 status+0x16、group count+0x1C/cursor+0x92；0x7A count+2/cursor+6 | 合法 extent、錯誤分支、第一個真實 Server response；可達 handler ≠ Server 必發 | T03/T02，RR-0003/0007 |
| **L03 選服與切線** | 0x13 有條件 local F4241，UI 選項另受 gate 才到 key0/key2 Connect | 選服來源與 socket/session handoff，F4241 非 wire 命令 | T02/T03，RR-0005（限定接受） |
| **L04 Frame／分派** | 0x0BBB checksum、0x2633 XOR/解壓、0x22D7/default raw、lane/scene gate | 何種 marker 真用、分段/缺包/校驗錯不同路徑；不可一律當斷線 | T02，RR-0001/0006/0007，REQ-0005 |
| **L05 角色清單** | S2C command2 `65+53×N`；0x4D4150 有界寫 UI record+0x5C | prefix 全語義、合法角色權威與字串/ID 政策；資料寫入不等於 UI 刷新 | T03/T04，RR-0002，REQ-0003 |
| **L06 清單後初始化** | 既有局部 26+ID request 與 FBA798 gate 線索 | 真正 request/reply pair、前置狀態、必要資料和錯誤分支 | T03/T04/T02，RR-0002/0007 |
| **L07 UI Ready** | 0x672F00 與 F4246/F4247／條件式 F4278 的有限 UI 消費路徑 | producer→投遞→訂閱→dialog/resource→可操作的完整鏈 | T03 主責 UI，T06 資源對應，REQ-0004 |
| **L08 實際可見** | **沒有**經授權真實 Client + 隔離 Server 成功觀察 | 有/無角色、資料錯誤、斷線等實測必須另行授權並保留 trace + 畫面 | S00＋獨立 Server 測試 |

`N=0` 是測試候選但不證明自動打開創角；既有角色選擇 C2S `0x42` **不能**當建立角色的命令，也無法單憑 S2C `0x42/0x43` handlers 推出官方選角成功／失敗配對。局部 F4241／F4246/47/78 是 **Client 內部事件**，不屬於 Server 傳輸命令。

## 4. Server 開發與需求來源

唯一 `design/requirements/index.json` 支援 `CODE_ANALYSIS`、另外授權的 `GAME_RUNTIME_OBSERVATION`、`PLAYER_ADMIN_REQUEST` 三來源；GM 權限、營運、安全、備份均歸玩家／管理員需求，歷史文件作請求附件，不另列原始 Server 真值來源。真正帳號政策、資料庫/Session 設計與部署在獨立 Server 庫以 ADR 審核，並非 Client 靜態分析可推出之原版 Server 規則。Server 實作 bug 照 FB 分流，第四來源未獲准不得加。
