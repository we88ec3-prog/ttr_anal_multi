# 未來外部 Issue 接收機制（**未啟用**）

現在只有維護者決定研究與規格更新；不建立 `.github/ISSUE_TEMPLATE/`，不要求其他開發者回報，也不承諾回覆外部內容。此處僅留交接規劃，公開庫的外部參與不受此文視為已接受。

## 待未來接手者明確決定後

1. 確認維護人力、回應政策與專案授權／可分享資料限制。
2. 明確決定 GitHub Repository 設定是否允許 Issues 與 Discussions；現階段不變更該設定。
3. 啟用模板：規格缺陷、協定缺口、Client 相容性、證據請求、設計提案；要求 SPEC ID、版本、最小重現及匿名化資料。
4. 對外回報由 S00 先初審，僅在證據充分時指派 Txx；不直接將外部說法升格為 NATIVE_VERIFIED。
5. 修規格、更新測試、標記新舊版本與受影響實作後才結案。
6. T01 的 **內部研究退回** 仍依 Task README 程序，和外部 Issue 完全分開。

此文不是對外徵件公告。
