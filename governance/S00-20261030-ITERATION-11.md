## 3. 本輪需求分流更新

每次 Txx 發現 Client 需要 Server 收發的行為，先對照唯一 `design/requirements/index.json` 的驗收條件。相同目標就追加 `CODE_ANALYSIS` discovery，附完整 Client SHA/CLM/條件/反例；不同真正需求才增 REQ。獲另行授權的 Client 運行可以追加 `GAME_RUNTIME_OBSERVATION`（環境、去敏證據、授權與版本）；玩家/管理員提案屬 `PLAYER_ADMIN_REQUEST`，包括權限、備份和營運需求。歷史協定/舊 Server 資料由該請求作附件，不能成為第 4/5 種自動核准的 Client wire evidence。Server 實作缺陷仍走 FB；是否增加 SERVER_IMPLEMENTATION_FEEDBACK 尚待使用者同意。

- `REQ` 是需求本身；`RR` 指派原生補證；`GAP` 是未解 Client/Spec 阻塞；`SPEC` 是有界的實作契約；`ADR` 是人工核准的 Server 自訂政策；`TEST` 註明證據等級。不同物件狀態永不互相自動升格。
- 新增的規劃腳本 `--check` **只對索引參照、版本與 DAG 結構不符報錯**；有 OPEN GAP 或 IN_REVIEW RR 時不算程式失敗。
- 空 `SLICE-CREATE.requirement_ids` 故意顯示 `DISCOVERY_REQUIRED`，不要為了讓 CI 變綠製造用戶需求、假裝真的觀察到創角動畫或封包。
- 純 Server 需求審批、角色權限政策、帳號驗證、管理者新功能須另走人為決策，不等於原版 Server 事實。
