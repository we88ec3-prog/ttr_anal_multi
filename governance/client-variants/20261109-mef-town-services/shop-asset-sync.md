# KR 普通商店購買類型與資產更新

來源為 `Tartaros.bin`，SHA256 `9741d1975327b9309d82b52f631165bc410757694d7c183a5eed970a53ebef91`。本篇為靜態指令證據。下方位置均為 VA，這些程式區段的檔案偏移等於 VA − `0x400C00`。

## 購買 context

`683E98..683ECB` 將商店表的 TYPE 傳入商品初始化 `681E10`。`681E38..681E75` 將 TYPE 保存到商品頁 `+CC`，並把 `+D0` 設為 1，TYPE 6 改成 3，TYPE 5 改成 4。`682A38..682A3F` 讀取這個欄位交給 C2S `0027` 送出。馮德斯雜貨 ShopNo 1 的 TYPE 是 1，因此這個買賣案例的 context 為 1。 [商店表與購買路徑](shop-services.md)

## S2C 002C

`4FDA3B..4FDA8A` 以 `4 + opcode × 8` 取 player-state handler。`4E1DDF` 把表偏移 `164h` 設為 `4E2420`，對應 `002C`。`4E2431` 呼叫 `509CE0`。`509D2D..509D57` 用 payload 的 +4、+8 覆寫本地資產欄 `+6864`、`+6870`。普通商品的價格判定 `682725..682738` 讀取 `+6864`，對應 LeeLoo。商店 context 4 的 `6827A2..6827B5` 將 `+6870` 與商品 `+2Ch` 的價格比較，`51C696..51C6D1` 從 `BATTLE_POINT`（`C0E624`）載入該價格。

Client 由 `(payloadBytes − 12) / 17` 計算格位記錄數。每筆固定 17 bytes，因此單格更新為 29 bytes。數量非零走 `50A38F → 508CB0`，數量為零走 `50A396..50A3BC` 清格。`50A418` 發出本地 UI 事件 `F4365`。賣出確認前的 `6029A5..6029EE` 同樣用背包 1、格位 1–100 讀取格內物品。更新先落盤再送給 Client，實際顯示與重登回讀留待驗收。
