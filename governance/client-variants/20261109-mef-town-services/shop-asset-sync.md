# KR 普通商店購買類型與資產更新

來源為 `Tartaros.bin`，SHA256 `9741d1975327b9309d82b52f631165bc410757694d7c183a5eed970a53ebef91`。本篇為靜態指令證據。下方位置均為 VA，這些程式區段的檔案偏移等於 VA − `0x400C00`。

## 購買 context

`683E98..683ECB` 將商店表的 TYPE 傳入商品初始化 `681E10`。`681E38..681E75` 將 TYPE 保存到商品頁 `+CC`，並把 `+D0` 設為 1，TYPE 6 改成 3，TYPE 5 改成 4。`682A38..682A3F` 讀取這個欄位交給 C2S `0027` 送出。馮德斯雜貨 ShopNo 1 的 TYPE 是 1，因此這個買賣案例的 context 為 1。 [商店表與購買路徑](shop-services.md)

## S2C 002C

`4FDA3B..4FDA8A` 以 `4 + opcode × 8` 取 player-state handler。`4E1DDF` 把表偏移 `164h` 設為 `4E2420`，對應 `002C`。`4E2431` 呼叫 `509CE0`。`509D2D..509D57` 用 payload 的 +4、+8 覆寫本地資產欄 `+6864`、`+6870`。普通商品的價格判定 `682725..682738` 讀取 `+6864`，對應 LeeLoo。商店 context 4 的 `6827A2..6827B5` 將 `+6870` 與商品 `+2Ch` 的價格比較，`51C696..51C6D1` 從 `BATTLE_POINT`（`C0E624`）載入該價格。

## S2C 0029 背包容量與格位初始化

`4E1DCF` 將 player-state 表偏移 `14Ch` 綁到 `4E23E0`，對應 `0029`。該 handler 將 payload、長度與同一個背包物件傳給 `509B90`。這條路徑只處理背包 1，從 payload +3 寫入容量欄 `+CA0h`，再按 `(payloadBytes − 4) / 16` 逐格處理。非零數量同樣經 `508CB0`，數量 0 清指定格。

| Payload 或列內偏移 | 寬度 | 欄位 |
|---|---|---|
| Payload +0、+2、+3 | u16 LE、u8、u8 | `0029`、背包種類 1、容量 |
| 首列 Payload +4，其後每 16 bytes | u8、u8 | 列內 +0 格位、+1 數量 |
| 列內 +2、+6、+12 | 各 u32 LE | 物品 metadata +10h、+14h、物品 ID |
| 列內 +10 | 2 bytes | 此 handler 未讀取 |

`509C8E..509CC1` 發出與 `002C` 相同的本地更新事件。Client player-state 建構函式 `4E1590` 在 `4E1971..4E19A3` 配置背包物件並存入 `F94300`（player-state 基底 `F8D9E0` + `6920h`），其後才在 `4E1AFF` 呼叫 handler 表初始化 `4E1DA0`。這確認背包配置早於 handler 註冊。原版在哪個登入階段收到完整資料仍待核對。靜態區段 `4E1DCF..4E1DDF` SHA256 `ee9e90e69c7455b634f5eb16f359d227714e988b5c85b4e22d8d622a8c2c621e`，`509C09..509C8E` SHA256 `2366f05649411a576b01f278588bae9921a106ad8303b962b1ee3e99322cb454`，範圍均左閉右開。

## S2C 0030 交易提示

`4B378A` 從 payload +2 讀取 u16 旗標。`4B3791` 先看 `0x10` 購買，`4B3A44` 再看 `0x08` 賣出。兩條分支都檢查 bit 0，購買未成功時另有 bit 1 的特殊分支。本機候選成功使用購買 `0x11`、賣出 `0x09`，一般失敗使用 `0x10`、`0x08`。資產仍由獨立的 `002C` 同步。

目前實機驗收仍在累積中。正式交易尚需接入 Battle Point 餘額與兩個物品 metadata 的來源，並驗證初次進村和重登時的背包同步。
