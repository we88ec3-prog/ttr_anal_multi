# KR 原版 Client 可讓關卡腳本接手哪些操作

2026-11-09 S00 離線交接。使用者表示原版 MEF 已不可取得，本次目標改為驗證關卡規則能取代哪些 Server 操作。沿用 REQ-0019、REQ-0021 及 Server 的 SFD-0015／0016；本次不提升 RR、SPEC、T01 驗證或人測狀態。研究基準為 `055e40018f35ce741df81364750afc5c0a844b06`，核對的 Server 程式是 `0f431e4830246193532de8cb40385641151f6d7a`。

**離線結論。** Client 有能力獨立執行已啟動的劇情、計算指定路段的中間位置、建立 NPC、開關已登記的互動點，並以原生資料組出對話、貨架和特定服務。一般村落或副本仍缺「哪個在該階段存活的腳本能接到事件並呼叫這些 API」的完整證據。舊格式的自動讀取與傳檔均保持未知。現有重建用 JSON 能提供規則；只有關閉某個 Server 指令後仍能完成的操作，才可另外算 Client 接手。

## 依操作判斷

| 操作 | 已用原件驗證 | 重建規則可決定／仍缺的交界 |
|---|---|---|
| NPC 的站位、面向 | `lb.CreateObjectEx` 與 S2C 0007 可走相同 CNPC 建構器。前者接受 XY、面向並由本地配號，後者採外來 EntityId。 | 可定義 NPC 站哪裡及何時出現。本地首次生成常駐 NPC 要補 Town1 腳本入口、與互動區一致的座標、兩端實體身分。現有 BND 候選點沒有原版 XY 證據。 |
| 商店位置 | MARKET 點 category 2 以 ShopNo 作鍵；原生 0027 消費位置、半徑、類別與鍵，Client 依 XY 放置市場標記。普通 NPC 互動點為 category 3。 | 腳本可描述落點，先由已證的點集合接口發布。已有點可由本地 setter 開關互動。目前未證一般村落腳本能單獨首次建立任意市場點。不可從 ShopInfo 名稱或 NPC 名冊猜商店座標。 |
| NPC 動作、說話、任務 | 劇情 Q API 有走位、動作、鏡頭與對話。世界 NPC 碰到適用分支時可在 Client 查對話並發本地 UI 事件，另有先本地選場景、再送互動通知的受限分支。 | 固定演出與已存在的對白可交由 Client；任務前置、替換常駐 NPC、跨玩家狀態與完成保存需獨立關聯。劇情槽號與可互動世界 EntityId 不共用。 |
| 開店／販賣什麼 | 市場點按 ShopNo 取得 NPC，視窗再以當前 Town＋NPC 查貨架與 Product；原表指定城鎮、商戶、商品與基準價格。 | 可在腳本中選擇既有店、位置、開放時機。本次未證能僅靠關卡檔覆寫任意貨架、替任意 NPC 新增服務，或把本地顯示價當實際成交。 |
| 買入／賣出 | 普通單筆購買 C2S 0027、背包出售 C2S 0020 有獨立 producer；S2C 0030 的已查分支選買／賣提示。S2C 0027 建點與 C2S 0027 買入是兩個方向。 | 關卡規則可管可用性或價格政策。Server 開發須核身份、貨單、數量、金錢與背包，落盤後刷新；收到一條可顯示的提示不能證明成交入帳。 |
| 鐵匠強化、其他服務 | Town1 Shop 2 → NPC 10030 → NPC type 12 → 功能 29 → F42F6 → 普通裝備強化窗。普通強化 C2S 00A1、結果顯示 S2C 00D9 已定位。 | 可透過既有商戶身分接入原生強化選單；消耗材料／費用、成敗或破損、裝備變更需 Server 明確裁決與保存。銀行商店、倉庫存取、鍊金、製作、拆解各走自己的契約；需分項驗收。 |
| 固定演出與怪物移動 | Q119/3 的 3 個演出物件有 5 次走位、6 次動作；已有戰鬥怪可憑 S2C 0018 的終點及更新步數自行步進。 | 可少逐步動作／座標指令。固定路段不決定仇恨、選招、命中；遇中斷與障礙的最終位置仍待驗。 |
| 生怪、清完一波、開門、換圖 | 本機可生成 CMonster；001A 按 ID 移除實體；已有出口的腳本開關與 S2C 0048 進同一 setter。教學收到 004C 後可續跑。lb.ChangeMap 可進載圖器。 | 可描述波次、條件、目的地；Field19 戰鬥階段收到清組事件的執行器仍未證。首次建門、開已建之門、Z 意圖、更新雙端進度分別驗收。 |

本輪暫把「MPC位置」按同句的 NPC 位置處理。原始 BIN 有 CNPC，已查的三份封裝成員名、所列原表及 BIN 字串未識別出獨立 MPC 類別。若 MPC 指另一類物件，需要其遊戲名稱或出現場景才能作同樣核對。

## Field19 清組事件追查

已核對 `4ADE8D → 4B28D0` 的 S2C 001A 分派、逐一取實體 ID 查共同 actor 索引，以及 `4B2AC2 → 4DFBC0` 清理。其移除動作不以「最後一隻」或 group ID 為必要條件。對教學情境，004C 只按情境 ID 寫結束旗標，與普通波次另域。另從原 BIN 定向追查了 22 個看似清場條件的 `kClearCondition_*`。它們是 857 筆文字描述目錄中的連續鍵 515–536，三 DWORD 列包含名稱指標及預設 `NOT DEFINED`，`58547D/585482` 將筆數及表首傳入載入器。這些列可識別清場文字，未提供「死亡 → 怪群已空 → 通知關卡」的 writer。這些限定路徑的結果不能涵蓋未閉合的間接 callback。

下一個離線檢查點是一般 Field19 的控制器生命週期、合法的群組成員與死亡訂閱者。不得把 001A、文字鍵、劇情收尾或教學旗標假定為一般清組通知。附錄另列出有依據的兩個替代驗收，分別是 Map191 已存在 actor 的短距移動，與預先登記後才開啟的出口。[場景與戰鬥操作的完整靜態證據](scenario-controls.md)

## Server 開發規劃
