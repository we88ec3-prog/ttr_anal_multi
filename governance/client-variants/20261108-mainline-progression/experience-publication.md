# S00／RR-0014　KR 角色經驗條更新

原始 KR `Tartaros.bin` SHA-256 為 `9741d1975327b9309d82b52f631165bc410757694d7c183a5eed970a53ebef91`。以下是該版本的靜態欄位證據，隸屬 GAP-PROGRESS-0001。

`0034` 由 `4B3090` 處理，2-byte opcode 後每筆 18 bytes。對有角色物件的第 1 類記錄，`4B3283–4B328E` 寫入本機帳號已初始化的角色記錄，並在 `4B3296–4B32B2` 依序經 vtable slots `+7C/+80/+78` 更新角色物件。原檔 `C075CC/C075D0/C075D4` 對應下表三個 setter，其他已核對的角色 vtable 也使用同一組。

| 單筆 payload 絕對位移 | 欄位 | 角色記錄 | 角色物件／setter |
|---|---|---|---|
| +02 | 類型 DWORD = 1 | | |
| +06 | 實體 ID WORD | | |
| +08 | 下級累積經驗門檻 | +58 | +3DC／4C8F80 |
| +0C | 本級累積經驗起點 | +54 | +3E0／4C8F70 |
| +10 | 目前累積經驗 | +50 | +3D8／4C8ED0 |

`CExpBar` 的 `5D5B80` 從當前控制角色取三值，`5D5C1F–5D5C2E` 讀取上述物件欄位，計算 `(目前 − 本級起點) / (下級門檻 − 本級起點)`，分母為零時顯示 0.0%，其餘以百分比格式化。`5CCD30` 的 HUD 刷新也使用同一公式。

`005C` 會寫入同一組角色記錄欄位及 level，並觸發任務可用性重算。既有 `005C` 的 DWORD +04/+08/+0C 依序對應目前／下級／本級起點。要驗收角色成長，應在角色記錄初始化後測量 `005C` 的等級與 `0034` 第 1 類的 HUD 更新，並以合法結算後能從 Q119 進 Q120 作端到端驗收。

Server 發放前仍須確定獎勵資格、受益角色、經驗值及升級曲線。這次只核對發布格式，實機尚待測。

Server 的經驗曲線由一組明確提供的累積經驗門檻定義。門檻從 0 起算、逐級遞增，恰達下一級門檻就使用下一級。測試曲線在最高級保留累積經驗，將本級起點與下級門檻設為同值，原版經驗條依零分母分支顯示 0.0%。最高級顯示為 Server 候選規則，待實機確認。等級與三個經驗值來自同一快照，先發布 `005C` 的角色記錄，再用 `0034` 更新已初始化的角色物件。正式曲線仍待提供，現有存檔和任務結算維持原流程。

已重讀原始 QuestInfo（SHA-256 `5d251415fdfdc453adefbff03114ded5a8ea41b696ce0aab86a23070e0fdca60`）的 Q119。該列只有 Demand118 與 RewardsEtc，沒有 `Contents` 或 `CompleteAction`。Q119/5 的劇情成員最後收尾對話、清理演出物件並恢復地圖。[Q119/5 場景呼叫記錄](../../../research/handoffs/s00-phindos-web-analysis-20261103/scenes/Q119-S5.json)

### Server 角色成長存檔

角色成長以帳號與角色索引為鍵，保存規則 ID、等級、目前累積經驗與本級／下級門檻。登入時在已授權的角色名冊讀取這份資料。正常地圖重建時，作用中的角色在綁定後收到 `005C` 與 `0034`。村莊隊伍顯示讀取相同快照，裝備等級門檻於裝備交易內從資料庫讀取。既有角色沒有成長資料時，沿用歷史初始等級。測試跳轉與技能場的顯示等級不構成裝備資格。

這一版的正流程驗證使用獨立資料庫中已寫入的合成角色資料。後續獎勵入帳須在同一交易更新成長存檔與獎勵帳本，提交後刷新當前連線的角色快照，才能在同一登入階段續接 Q120。正式升級曲線、發放資格、首次引入既有帳號的政策及實機驗收仍待完成。
