# S00／RR-0014　KR 角色經驗條更新

原始 KR `Tartaros.bin` SHA-256 為 `9741d1975327b9309d82b52f631165bc410757694d7c183a5eed970a53ebef91`。以下是該版本的靜態欄位證據，隸屬 GAP-PROGRESS-0001。

Server 啟用主線經驗政策時，正常的主線 NPC 互動以目前擁有角色的最高等級核對主線資料的 `levelRaw`。角色先取已存等級，缺值時使用該政策的初始等級，村莊公布給 Client 的等級沿用同一取值規則。Q133 的門檻為 10，選用低於 10 的角色仍可對話，前提是另一名已擁有角色達到 10。進度指定與未啟用經驗政策的舊模式沿用原流程。此核對屬 Server 對既有主線路徑的實作，正式任務接取、交付與獎勵仍各有驗收。 [Client 等級門檻證據](../20261107-town2-npc-marker/README.md)

`0034` 由 `4B3090` 處理，2-byte opcode 後每筆 18 bytes。對有角色物件的第 1 類記錄，`4B3283–4B328E` 寫入本機帳號已初始化的角色記錄，並在 `4B3296–4B32B2` 依序經 vtable slots `+7C/+80/+78` 更新角色物件。原檔 `C075CC/C075D0/C075D4` 對應下表三個 setter，其他已核對的角色 vtable 也使用同一組。

| 單筆 payload 絕對位移 | 欄位 | 角色記錄 | 角色物件／setter |
|---|---|---|---|
| +02 | 類型 DWORD = 1 | | |
| +06 | 實體 ID WORD | | |
| +08 | 下級累積經驗門檻 | +58 | +3DC／4C8F80 |
| +0C | 本級累積經驗起點 | +54 | +3E0／4C8F70 |
| +10 | 目前累積經驗 | +50 | +3D8／4C8ED0 |

`CExpBar` 的 `5D5B80` 從當前控制角色取三值，`5D5C1F–5D5C2E` 讀取上述物件欄位，計算 `(目前 − 本級起點) / (下級門檻 − 本級起點)`，分母為零時顯示 0.0%，其餘以百分比格式化。`5CCD30` 的 HUD 刷新也使用同一公式。

`005C` 會寫入同一組角色記錄欄位及 level，並觸發任務可用性重算。既有 `005C` 的 DWORD +04/+08/+0C 依序對應目前／下級／本級起點。要驗收角色成長，應在角色記錄初始化後測量 `005C` 的等級與 `0034` 第 1 類的 HUD 更新，並以合法結算後能從 Q119 進 Q120 作端到端驗收。

Server 發放前仍須確定獎勵資格、受益角色、經驗值及升級曲線。這次只核對發布格式，實機尚待測。

Server 的經驗曲線由一組明確提供的累積經驗門檻定義。門檻從 0 起算、逐級遞增，恰達下一級門檻就使用下一級。測試曲線在最高級保留累積經驗，將本級起點與下級門檻設為同值，原版經驗條依零分母分支顯示 0.0%。最高級顯示為 Server 候選規則，待實機確認。等級與三個經驗值來自同一快照，先發布 `005C` 的角色記錄，再用 `0034` 更新已初始化的角色物件。正式曲線仍待提供，現有存檔和任務結算維持原流程。

### Q119 的副本完成證據

已重讀原始 QuestInfo（SHA-256 `5d251415fdfdc453adefbff03114ded5a8ea41b696ce0aab86a23070e0fdca60`）的 Q119。該列只有 Demand118 與 RewardsEtc，沒有 `Contents` 或 `CompleteAction`。Q119/5 的劇情成員最後收尾對話、清理演出物件並恢復地圖。[Q119/5 場景呼叫記錄](../../../research/handoffs/s00-phindos-web-analysis-20261103/scenes/Q119-S5.json)

Server 的正常副本路線，在權威副本狀態已走到終點且返回流程完成後，於同一資料庫交易推進主線並在 `local_story_events` 附上 `ScenarioCompletion`。內容是任務 ID、副本定義 ID、已載入的副本目錄 SHA-256、終點節點、已通過的出口及參戰角色。續玩快照只保留主線游標，歷史事件保留其原始雜湊。測試跳轉及舊存檔沒有補造通關證據。這筆資料可供後續核對候選發放資格，正式收件人、數值、入帳及補發規則仍待完成。

### Server 角色成長存檔

角色成長以帳號與角色索引為鍵，保存規則 ID、等級、目前累積經驗與本級／下級門檻。登入時在已授權的角色名冊讀取這份資料。正常地圖重建時，作用中的角色在綁定後收到 `005C` 與 `0034`。村莊隊伍顯示讀取相同快照，裝備等級門檻於裝備交易內從資料庫讀取。既有角色沒有成長資料時，沿用歷史初始等級。測試跳轉與技能場的顯示等級不構成裝備資格。

這一版的正流程驗證使用獨立資料庫中已寫入的合成角色資料。後續獎勵入帳須在同一交易更新成長存檔與獎勵帳本，提交後刷新當前連線的角色快照，才能在同一登入階段續接 Q120。正式升級曲線、發放資格、首次引入既有帳號的政策及實機驗收仍待完成。

### 可設定的 Server 經驗結算

候選結算可由 `tartaros.server.story-experience.v1` JSON 啟用。必要欄位為 `schema`、`storySha256`、`scenarioCatalogSha256`、`levelThresholds` 與 `rewards`。每筆獎勵指定 `quest` 與正整數 `experience`，只對指定的有副本任務生效。接收者採完成事件的參戰角色。沒有存檔時先以原 Server 初始等級對應的本級門檻起算。這兩項屬 Server 候選政策。

正式路線的終點證據與路線版本相符後，Server 在同一 SQLite 交易保存主線進度、完成事件、經驗帳本及角色累積經驗。帳本以帳號及任務 ID 為鍵。同帳號的已入帳任務不重發。角色經驗以規則檔 SHA-256 保存，切換規則時需要明確的資料移轉。交易提交後，當前連線在下一次世界重建用更新後的等級和經驗發布角色狀態。

本輪只驗證合成經驗政策。正式 Q119 金額、曲線、受益範圍及舊帳號補發仍待確認。未指定規則檔時不啟用經驗發放。此 JSON 為 Server 自訂資料，分類為 `NOT_NATIVE_MEF`。

### Q119 至 Q120 測試候選

以 Q119 原表顯示的 5,850 隊伍經驗作為本地候選獎勵，由實際參戰角色領取。Lv.1–10 累積門檻暫定為 `0, 100, 300, 600, 1000, 1700, 3000, 5600, 7800, 10500`，用於驗證這一段主線。角色 1、3 的舊初始等級為 Lv.5，從 1,000 起算，結算後累積 6,850。角色 4 的舊初始等級為 Lv.2，從 100 起算，結算後累積 5,950。三者都達到 Lv.8。

候選規則綁定 `alsmeer-mainline-route-v2.json` 與該版本未覆寫的副本圖。離線驗收檢查 Q119 返回後，Server 先發布 `005C` Lv.8 及 `0034` 經驗，再送 `006F` 前置快照，含 Q119 完成鍵，並可接到合成的 Q120 對話。Client 顯示及可接取須實機確認。候選只涵蓋這次 Q119 結算，Q121 以上及已完成 Q119 的帳號另有成長與補發工作。

### 馮德斯至爾勒梅斯主線經驗候選 v2

Q120 原始列只有 Demand119，沒有獎勵。Q121 要求 Lv.9 與 Demand120，Q122 要求 Demand121。完整候選把 Lv.9 門檻設為 5,600，因此第一次結算 Q119 後可繼續 Q120、Q121，兩個對話任務皆沿用原始獎勵欄位。一般練功副本的經驗來源尚未定位。

這份候選沿用 QuestInfo 的十筆副本 PartyExp 顯示值，由參戰角色領取。金額依序為 Q119 5,850、Q122 9,686、Q124 13,086、Q132 15,850、Q134 19,210、Q136 27,690、Q138 33,640、Q140 39,210、Q142 45,720、Q144 35,024。Server 暫定累積門檻由 Lv.1 到 Lv.16 為 `0, 100, 300, 600, 1000, 1700, 3000, 4500, 5600, 13000, 17000, 19000, 27000, 33000, 39000, 45000`。這個試驗上限覆蓋此路線。日後擴充等級須另訂版本與移轉規則。

[原版任務可用性分析](../20261107-town2-npc-marker/README.md)確認 Client 取所有有效角色的最高等級。正常登入名冊會發布已有存檔角色的等級與累積經驗。啟用候選政策時，村莊在更新任務前置前會再發布非當前角色的存檔或初始等級。`0034` 經驗條只更新目前角色。離線驗證枚舉了三名角色在十個副本中的 59,049 種參戰排列，逐步檢查 22 個任務的等級門檻。跨角色切換時的 Client 標記與實際可接取仍待驗收。

這是獨立的 Server 設定，分類為 `NOT_NATIVE_MEF`。適用於未啟用過其他經驗政策的測試資料庫。v1 已經入帳的角色資料需要移轉才能切換，已通關帳號的歷史補發仍待處理。

### 已通關帳號的登入補發

啟用經驗政策後，正常登入會在發布角色名冊前補發有完整完成事件的舊紀錄。核對項目包含有效帳號租約、已命名冒險團、該角色仍屬同一帳號、事件與路線版本一致、副本目錄雜湊一致、任務已走過終點與對應返回流程，以及同帳號該任務仍無發放紀錄。補發依完成事件順序處理，沿用正常結算寫入經驗帳本與角色成長。帳本記錄原完成事件的版本，主線進度及歷史事件維持原值。

只有游標前綴的早期存檔，包含可能早於新增 `ScenarioCompletion` 的 Q119 通關，仍需要可核對的通關紀錄或另行制定處理方式。其他曲線已入帳的角色須先移轉政策。本輪驗證以隔離 SQLite 資料庫進行，現行資料庫未套用。
