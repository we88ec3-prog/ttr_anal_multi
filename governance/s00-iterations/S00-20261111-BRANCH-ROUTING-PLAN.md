# S00：副本分支出口接續規劃

本輪在v94人測期間核對現有執行器。這是待開發規劃，不是假定已能分支。
關卡／MEF功能目標仍包含完整分支，不能只以目前有限線性鏈收尾。

## 已有能力與實際限制

目前資料是有限Entry→GroupCleared→InteractZ，每個節點一個預設出口。
NextNode action已帶目標，故事游標會按已核准的目標節點定位，而非必定加一；
但內容編譯器仍建立線性鏈，validator也只沿單一出口驗證可達性。
世界層先檢查目前位置／出口，再讓故事路由規劃交易；路由目前用預設出口中心
重建事件。因此只增加JSON分支欄位會讓不同出口最後都進預設路線，不能算完成。

## 下一批實作要求

1. 在同一節點明示多個有唯一key的出口及各自目標，保留既有單出口內容。
2. 共用資料驗證需涵蓋所有分支：目的節點存在、有限無環、所有定義可達且
   每條可選路線都能到結果，不以抽一條路通過代表整張圖。
3. 世界層以實際已授權的出口key／當前位置選擇，故事交易傳遞同一選擇，
   不再以預設中心取代它。重疊出口必須有可重現的選擇規則或禁止重疊。
4. 清組前全部關閉，清組後發布已允許出口；換圖後舊點生命週期必須清楚。
   沿用已知點登記／狀態訊息，不發明Client傳檔或選項opcode。
5. 分支只改該副本實例路徑，保持主線任務授權與結算保存界線。既有固定兩圖
   保存階段不能默默允許跳過任務節點；先接一般內容執行器與隔離測試場。
6. 正流程至少覆蓋兩個不同出口實際到不同圖、匯流後正常結算，以及交易規劃
   未提交前不改目前游標。安全／錯誤／循環／重送等套件仍依排程暫緩。

分支與條件旗標、道具檢查、Client本地腳本入口是不同項目，分別驗收。
不得把選招血量條件或拆開的增援測試誤算成副本圖序分支已完成。
