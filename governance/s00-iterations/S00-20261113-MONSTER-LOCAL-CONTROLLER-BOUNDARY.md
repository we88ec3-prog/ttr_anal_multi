# 普通怪本地建立與控制器掛接補證

原始 KR `Tartaros.bin`，SHA-256 `9741d1975327b9309d82b52f631165bc410757694d7c183a5eed970a53ebef91`。本輪比對原件控制器 vtable 與有關指令視窗。沿用 [場景接口](../client-variants/20261109-mef-town-services/scenario-controls.md) 和 [怪物權威界線](../client-variants/20261108-monster-authority-boundary/README.md) 的建立、共同 actor 索引、固定路段及來源限制。

## 觀察

- `lb.CreateObjectEx` 在 `4A11C1` 讀第六參數。非零時取得目前控制器 `[FBA7A4]`，在 `4A11D6` 帶 actor 呼叫 vtable `+04`，於 `4A11E3` 呼叫 `+10`。該選項本身未選擇控制器種類。
- CSingleController `C0FAC4` 和 CTutorialController `C0FB1C` 的兩個槽都解析為 `545040` 與 `5F5D10`。前者檢查三個、間距 12 bytes 的槽，在 `5450A2` 寫入 actor 指標，後者直接返回。
- CFormationController `C0FA14` 的對應槽是 `5476D0` 和 `5478F0`。`5476F8` 呼叫共用登記 `545040`，`54772F` 呼叫 `549490`，可將 actor ID 或既有 16-byte 紀錄放入三個暫存槽之一。第二槽在 `547945` 呼叫 `549530`，後者將暫存紀錄搬入同一管理器的工作槽。這表示「能登記 ID」與「能執行該模型的招式」需分別驗證。
- 已知 SubAI 攻擊執行器 `549C60` 於 `549CEE` 讀取 model key 低 WORD，`549CFB–549CFE` 跳過大於 9 的模型。普通怪 1036 不通過這條路徑。此條件僅涵蓋該執行器與已解析的控制器，其他決策器仍未知。

## 開發界線與後續驗證

| 能力 | 證據與進度 |
|---|---|
| Client 本地建立 CMonster | 有既有 `lb` 接口及本地配號證據。普通副本可用的啟動來源，以及本機 EntityId 與 Server 實例對齊仍待驗。 |
| Client 本地播放與移動 | v92 固定路段有實機結果。Server 指定路段及待機，Client 負責路段內步進。 |
| Client 自主索敵、選招、命中 | 已知掛接路徑尚不足以執行普通怪 1036 的攻擊。須找到實際決策來源及對應動作、受擊、移除邊界。現行 Server 保留這些裁決。 |
| 原生 `.mef` | 樣本、格式、接收及場景進入的消費鏈仍未證實。現行 Server 自訂關卡使用獨立格式 `NOT_NATIVE_MEF`。 |

後續先追普通副本進場時的控制器選擇與普通怪動作 producer。只有找到可達、可重現的原版啟動入口，才排本地生成對照，逐項核對 Server 不下發生成時能否建立實體、ID 如何對齊，及停止下發動作後是否有獨立索敵和選招。命中／HP／清組結果另核對，不以動畫代替。現有正常建隊進村與批次待測保持待排程。

重現方式：在原件 SHA 一致的前提下，依 PE section 映射讀取下列位址，32-bit x86 解碼。REA 用於開啟與核對原件身分，以下是直接依原件核對的限定視窗。
